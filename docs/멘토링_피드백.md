# 멘토링 피드백 (2026-08-21)

원문 그대로 두고, 각 항목이 우리 코드 어디에 해당하는지 대조합니다.
**이 문서가 이후 실험 우선순위의 근거입니다.**

---

## 원문

1. multi scale 로 augmentation 할 때 scale 변화되는 범위의 **폭을 줄여보는** 시도를 해도 좋을듯
2. 서비스 만들 때는 **정확도가 가장 높은 scale 로 촬영하도록 가이드**
3. 멀티 클래스의 경우 **confusion matrix** 로 어떤 클래스끼리 착각을 많이 하는지 판단해서
   학습데이터도 **정성평가** 해보고, 데이터를 직접 교정해주거나 **클래스 자체를 수정**하는
   작업이 필요할 수도 있음
4. augmentation 기법들도 **다양하게** 시도
5. **정성평가가 꼭 들어가야 함.** 어떤 케이스에 잘 못하는지 직접 찾아내고 판단해서
   개선 포인트를 찾아가는 것. 전처리·후처리 가릴 것 없이 전부 적용할 수 있게 시도.
   보통 후반부에 진행
6. **초반에는 최대한 빠르게 자동으로 시도해볼 수 있는 것들** 시도하기
7. augmentation 할 때는 **무조건 학습 중 실시간으로 랜덤**으로 진행해야 함. **albumentations**
8. **input size** 도 모델의 종류나 데이터의 특징에 따라 잘 정해야 함

---

## 우리 상태와 대조

| | 피드백 | 현재 | 조치 |
|---|---|---|---|
| 1 | scale 폭을 **줄여보기** | 넓히기만 2회 (`scale_robust`, `zoom_both`) — **좁혀본 적 없음** | 프리셋에 좁힌 범위 추가 |
| 2 | 최적 scale 로 촬영 가이드 | 교란 표에 이미 데이터 있음 (1x 가 최고) | **학습 0회로 결정 가능** |
| 3 | confusion matrix → 클래스 검토 | 그림은 그리지만 **숫자로 안 뽑고, 행동한 적 없음** | 혼동 쌍 상위 N개 출력 |
| 4 | 증강 기법 다양하게 | RRC/flip/rotate/jitter/erasing 5종뿐 | albumentations 로 확장 |
| 5 | **정성평가** | **전혀 없음** | 오분류 케이스 뷰어 필요 |
| 6 | 초반엔 빠르게 자동으로 | 실험 1회 = **4.5시간** ← 반대로 하는 중 | 서브셋 빠른 스윕 도입 |
| 7 | 실시간 랜덤 증강 | ✅ 이미 그렇게 함 (`SkinDataset.__getitem__`) | albumentations 전환은 별건 |
| 8 | input size 신중히 | ✅ 224 → 384 를 실측으로 결정 | 04 에서 모델별로 다시 |

### 가장 뼈아픈 지적: 6번

지금 증강 프리셋 3종을 비교하려고 **4시간 30분**짜리 풀 학습을 돌리려던 참이었습니다.
멘토 조언은 정확히 그 반대입니다 — **초반엔 싸게 많이 돌려보고, 확정만 비싸게** 합니다.

바꿀 것:

```
지금:  프리셋 3종 × 풀 데이터 × 30에폭  =  4.5시간   → 3개밖에 못 봄
바꿈:  프리셋 8종 × 서브셋   × 12에폭  =  2시간     → 8개를 보고
       상위 2종 × 풀 데이터 × 30에폭  =  3시간     → 확정
```

⚠️ 서브셋에서 이긴 프리셋이 풀 데이터에서도 이긴다는 **보장은 없습니다.**
그래서 확정은 반드시 풀 스케일로 다시 합니다. 스윕은 **후보를 줄이는 용도**입니다.

### 7번 — 절반은 이미 하고 있었습니다

증강은 `SkinDataset.__getitem__` 안에서 매 호출마다 적용됩니다. 즉 **에폭마다 다른
난수**가 걸리는 실시간 랜덤이고, 미리 만들어 저장하는 방식이 아닙니다.

바꿀 부분은 **라이브러리**입니다. 지금은 torchvision(PIL 기반)인데,
`bench.report` 실측에서 **증강·변환이 18.0ms** 로 파이프라인 병목입니다:

```
디코딩      9.5 ms
증강·변환  18.0 ms   ← 여기
→ 실제 처리량 90 img/s (GPU 는 112 img/s 로 놀고 있음)
```

albumentations 는 numpy + cv2 기반이라 대개 훨씬 빠릅니다. 전환하면
**속도(6번)와 기법 다양성(4번)을 한 번에** 얻습니다.

### 2번 — 이미 답이 나와 있습니다

교란 검사가 배율별 점수를 이미 재고 있습니다 (2단계 384px):

| 배율 | macro-F1 |
|---|---:|
| 0.5x (멀리서) | 0.4066 |
| 0.71x | 0.4920 |
| **1x (기준)** | **0.5489** ← 최고 |
| 1.41x | 0.5205 |
| 2x (가까이) | 0.4632 |

**1x 가 최고이고, 여기서 1x 는 "m1.5 크롭" = 병변이 화면의 약 2/3를 차지하는 구도**입니다.
촬영 가이드 문구를 이 숫자로 정할 수 있습니다 — 학습 한 번 더 안 돌려도 됩니다.

### 3번 — 클래스를 건드리는 건 신중하게

혼동 쌍을 보고 클래스를 합치는 건 강력하지만 되돌리기 어렵습니다.
우리 데이터에는 이미 단서가 있습니다:

* A1(구진·플라크)은 **하한선(0.529) 대비 CNN(0.576) 격차가 +0.047 뿐** — 사진에서
  거의 못 배우고 있습니다
* A6(결절·종괴)는 **하한선보다 낮습니다** (0.453 → 0.405)

둘 다 "사진으로 구분이 어려운 클래스" 후보입니다. 다만 **합치기 전에 정성평가로
눈으로 확인**해야 합니다 (5번). 숫자만 보고 합치면 임상적으로 중요한 구분을
잃을 수 있습니다 — A6 은 종양 감별이라 특히 그렇습니다.
