## 지표 자체는 이미 아시는 것

precision, recall, F1, AUROC — 머신러닝에서 보신 것과 **정의가 완전히 같습니다.**

이 문서는 정의를 다시 설명하지 않습니다. 대신 **읽는 법**을 다룹니다.
우리 문제에서는 같은 숫자를 다르게 해석해야 하거든요.

---

## 규칙 1: accuracy 단독 보고 금지

우리 데이터가 이렇다고 해봅시다:

```
A2: 40%   A1: 20%   A3: 15%   A4: 12%   A6: 10%   A5: 3%
```

**"무조건 A2"라고 찍는 모델의 accuracy = 40%.**
쓸모는 정확히 0인데 숫자는 그럴듯합니다.

게다가 이 모델이 놓치는 A5(미란·궤양)는 **임상적으로 더 급한** 병변입니다.
가장 중요한 걸 못 맞히는 모델이 높은 점수를 받는 구조입니다.

### 대신 볼 것

```python
rep = evaluate.full_report(logits, y, CLASSES)
```

```
macro-F1          : 0.7412   (95% CI 0.7103 – 0.7698)   ← 주 지표
balanced accuracy : 0.7255
accuracy          : 0.7801   ← 참고만
```

- **macro-F1**: 클래스별 F1 의 **단순 평균**. 희소 클래스도 동등하게 취급 → 버리면 떨어짐
- **weighted-F1**: 클래스 크기로 가중 평균 → accuracy 와 비슷하게 속기 쉬움
- **balanced accuracy**: 클래스별 recall 의 평균

> 💡 우리 `cfg.monitor = "macro_f1"` 인 이유입니다.
> 조기 종료와 best 체크포인트 선택 모두 이 기준으로 합니다.

## 규칙 2: 클래스별 recall 을 반드시 보세요

평균은 최악을 숨깁니다.

```
클래스                        precision   recall      f1       n
A1 구진·플라크                      0.781    0.812   0.796   1,240
A2 비듬·각질·상피성잔고리                0.856    0.903   0.879   2,410
A3 태선화·과다색소침착                  0.723    0.688   0.705     902
A4 농포·여드름                      0.690    0.712   0.701     735
A5 미란·궤양                       0.612    0.421   0.499     187   ← ⚠️
A6 결절·종괴                       0.702    0.655   0.678     603
```

macro-F1 은 0.71 로 나쁘지 않은데, **A5 의 recall 이 0.42** 입니다.

> 미란·궤양이 있는 강아지의 **58%를 놓친다**는 뜻입니다.

그리고 A5 는 피부 장벽이 무너진 상태라 조기 진료가 필요한 병변입니다.
A6(결절·종괴)는 악성 종양 감별이 필요하고요.

**우리 서비스에서 가장 놓치면 안 되는 것을 가장 많이 놓치고 있습니다.**

`evaluate.py` 가 이걸 자동으로 짚어줍니다:

```
⚠️ recall 최저: A5 (미란·궤양) = 0.421
   → 이 병변이 있는 강아지 58% 를 놓칩니다.
```

## 규칙 3: 오류의 비용이 대칭이 아닙니다

| | 미탐 (놓침) | 오탐 (헛알림) |
|---|---|---|
| 무슨 일 | "정상"이라 해서 병원 안 감 | 병원 갔는데 괜찮음 |
| 비용 | 질환 진행, 최악의 경우 악성 종양 방치 | 진료비 몇 만원 |
| 체감 | **회복 불가능할 수 있음** | 짜증 |

**비용 차이가 100배쯤 납니다.** 그래서 recall 을 precision 보다 우선합니다.

```python
cfg.target_recall_stage1 = 0.95
```

1단계(정상/이상)에서는 **recall 0.95를 먼저 고정**하고,
그 조건에서 precision 이 얼마인지를 확인합니다:

```python
evaluate.binary_report(scores, y_bin, target_recall=0.95)
```

```
recall ≥ 95% 를 만족하는 임계값: 0.2841
  그때 precision = 0.412, recall = 0.951
  → 이상이라고 알린 것 중 59% 는 실제로는 정상입니다.
```

**precision 0.41이 나쁜 걸까요?** 스크리닝 보조로는 괜찮을 수 있습니다.
"의심되니 확인해보세요" 10건 중 4건이 진짜면, 놓치는 것보다 낫습니다.
다만 너무 자주 울리면 사용자가 무시하게 되니(alarm fatigue) 균형이 필요합니다.

## 규칙 4: 혼동행렬로 "어떻게 틀리는지" 보기

```python
rep.plot_confusion()
```

```
        예측
정답     A1    A2    A3    A4    A5    A6
A1     0.81  0.08  0.04  0.05  0.01  0.01
A2     0.06  0.90  0.02  0.01  0.01  0.00
A3     0.09  0.05  0.69  0.02  0.03  0.12   ← A6 과 12% 혼동
A4     0.14  0.03  0.02  0.71  0.08  0.02
A5     0.05  0.04  0.06  0.18  0.42  0.25   ← A6 과 25% 혼동
A6     0.03  0.02  0.15  0.03  0.12  0.66
```

**모든 혼동이 똑같이 나쁜 게 아닙니다:**

- A1 ↔ A2 혼동: 둘 다 관찰 수준. 실무 영향 작음
- **A5 → A6 혼동 (25%)**: 둘 다 진료 권장이라 실무적으로는 덜 위험
- **A6 → A2 혼동**: 종괴를 비듬으로 봄 → **위험**. 진료를 안 가게 됨

즉 **"위험도가 높은 병변을 낮은 병변으로 오인하는 방향"** 이 진짜 문제입니다.
혼동행렬의 대칭성이 아니라 **방향**을 보세요.

## 규칙 5: 신뢰구간 없는 숫자는 절반만 믿기

```
macro-F1: 0.7412 (95% CI 0.7103 – 0.7698)
```

검증셋이 500장이면 ±0.03 정도는 그냥 흔들립니다.

```python
evaluate.compare_models({"convnextv2": rep_a, "effnetv2": rep_b})
```

```
     model  macro_F1  CI_low  CI_high
convnextv2    0.7612  0.7301   0.7889
 effnetv2_s   0.7488  0.7166   0.7783    ← CI 가 겹침
```

**0.7612 vs 0.7488 은 "다르다"고 말할 수 없습니다.**
구간이 [0.730, 0.789] 와 [0.717, 0.778] 로 크게 겹치니까요.

이걸 무시하고 "ConvNeXt 가 더 낫다" 고 결론 내리면,
다음 fold 에서 뒤집혀서 혼란스러워집니다.

**진짜 차이를 보려면**: 5-fold 교차검증 평균 ± 표준편차.

## 규칙 6: 검증셋과 holdout 의 차이

```
검증셋(val)  — 모델 선택, 하이퍼파라미터 조정, 임계값 결정에 사용
holdout      — 모든 결정이 끝난 뒤 딱 한 번. 최종 보고용
```

검증셋을 100번 보고 고르면, 검증셋에도 과적합됩니다.
"검증 macro-F1 0.78" 은 이미 낙관적인 숫자입니다.

**holdout 이 val 보다 유의미하게 낮으면** 검증셋 과적합이 일어난 것입니다.

```python
ho = split.get_holdout(df)    # 개체 단위로 미리 떼어둔 15%
```

> ⚠️ holdout 결과를 보고 하이퍼파라미터를 고치는 순간 그건 더 이상 holdout 이 아닙니다.

## 우리 프로젝트의 판정 기준

노트북 05 마지막의 체크리스트:

- [ ] holdout macro-F1 이 val 과 크게 다르지 않다 (차이 > 0.05 면 검증셋 과적합)
- [ ] **모든 클래스 recall ≥ 0.5**
- [ ] A5, A6(위험 병변)의 recall 이 특히 높다
- [ ] 보정 후 ECE < 0.10
- [ ] Grad-CAM 이 병변을 보고 있다

**현실적인 목표치** (개체 단위 분할 기준):

```
6종 macro-F1        0.70 ~ 0.80
1단계 정상/이상 recall  ≥ 0.95
```

> ⚠️ 개체 단위 분할에서 0.95+ 가 나왔다면 **누수를 의심하세요.**
> 축하할 숫자가 아니라 검증해야 할 숫자입니다.

---

## 흔한 오해 3가지

**❌ "AUROC 가 0.93이니 좋은 모델"**
AUROC 는 **모든 임계값에 걸친** 순위 능력입니다.
실제 서비스는 임계값 **하나**를 정해서 씁니다.
AUROC 0.93 이어도 실제 운영 임계값에서 recall 이 0.4일 수 있습니다.

**❌ "F1 이 높으면 배포해도 된다"**
Grad-CAM 검증을 통과해야 합니다. 배경을 보고 맞히는 모델은
검증셋에서만 잘하고 실사용에서 무너집니다.

**❌ "지표를 다 계산했으니 됐다"**
숫자보다 **실제 예측 사례**를 보세요. 틀린 것 20장을 직접 보면
지표 100개보다 많은 걸 알게 됩니다. (노트북 05에 있습니다)
