# 08. 확률 보정과 임계값 결정

> **읽는 시점**: STEP 5(평가) 전
> **왜 중요한가**: 이게 "의심된다"를 말할 자격을 만듭니다

---

## 문제: 신경망은 거짓말을 합니다

softmax 출력이 0.95 라고 해서 "95% 확률로 맞다"는 뜻이 아닙니다.

실제로 측정해보면 이런 일이 흔합니다:

```
"95% 확신" 이라고 한 예측 100건  →  실제로는 71건만 정답
"70% 확신" 이라고 한 예측 100건  →  실제로는 52건만 정답
```

이걸 **과신(overconfidence)** 이라고 합니다.
현대 신경망의 알려진 특성이고, 모델이 깊고 클수록 심해집니다.

### 우리에게 왜 치명적인가

우리는 이런 문구를 보호자에게 보여줄 계획입니다:

> 🔎 **비듬·각질** 형태의 병변이 의심됩니다. **(신뢰도 72%)**

그 72%가 실제로는 48%라면, **사용자에게 거짓말을 하는 것**입니다.
보호자는 그 숫자를 보고 병원에 갈지 말지를 정할 텐데요.

일반 이미지 분류라면 "고양이 95%"가 틀려도 웃고 넘어갑니다.
의료 맥락에서는 아닙니다.

---

## 해결: 온도 스케일링

놀랍도록 간단합니다. **logits 를 상수 T 로 나눕니다.**

```python
probs = softmax(logits / T)
```

- `T > 1` → 확률이 평평해짐 (과신 완화) ← 대부분 여기
- `T = 1` → 원래 그대로
- `T < 1` → 확률이 뾰족해짐

### 왜 이게 통하나

**T 는 순위를 바꾸지 않습니다.** logits `[3.0, 1.0, 0.5]` 를 2로 나누면
`[1.5, 0.5, 0.25]` — 크기 순서가 같습니다.

즉:
- **정확도는 그대로** (argmax 가 안 바뀜)
- **확률의 자신감만** 조정됨

파라미터가 딱 1개라 과적합할 여지도 거의 없습니다.
가장 단순하면서 가장 효과적인 보정 방법입니다.

```python
T = calibrate.fit_temperature(val_logits, val_y)
probs = calibrate.apply(test_logits, T)
```

### ⚠️ 반드시 지킬 것

> **T 는 검증셋으로 학습하고, holdout 에서 효과를 확인합니다.**

holdout 으로 T 를 맞추면 그것도 과적합입니다.
그리고 T 를 맞추는 데 쓴 데이터의 ECE 는 당연히 좋게 나옵니다.

## 보정 품질 측정: ECE

**Expected Calibration Error** — "주장한 확신"과 "실제 정답률"의 평균 차이.

```
확신 구간      건수    평균 확신   실제 정답률   차이
0.5 ~ 0.6      120      0.55        0.51       0.04
0.6 ~ 0.7      210      0.65        0.58       0.07
0.7 ~ 0.8      340      0.75        0.63       0.12   ← 과신
0.8 ~ 0.9      280      0.85        0.70       0.15   ← 심한 과신
0.9 ~ 1.0      150      0.95        0.78       0.17   ← 매우 심함

ECE = 건수로 가중평균한 차이 = 0.118
```

**해석 기준:**

| ECE | 판정 | 조치 |
|---|---|---|
| < 0.05 | 양호 | 확률 그대로 노출 OK |
| 0.05 ~ 0.10 | 보통 | 노출 가능, 반올림해서 |
| > 0.10 | 나쁨 | **숫자 노출 금지.** "높음/보통/낮음" 밴드로만 |

```python
calibrate.report(logits_val, y_val, logits_ho, y_ho)
```

```
  ECE  0.1183 → 0.0341
  MCE  0.2104 → 0.0812
  정확도 0.7612 → 0.7612   (변하지 않는 게 정상)
```

## 임계값 결정 — 언제 답하고 언제 물러설까

보정된 확률이 있으면 이제 **"모르면 모른다고 하기"** 를 설계할 수 있습니다.

### coverage–risk 곡선

```python
calibrate.coverage_risk_curve(probs, y)
```

```
답한 비율 → 오답률
  100%  →  28.4%   (신뢰도 임계값 0.000)
   90%  →  21.1%   (0.412)
   80%  →  14.7%   (0.531)   ← 20% 를 포기하면 오답률이 절반
   70%  →  10.2%   (0.628)
   50%  →   4.8%   (0.784)
```

**읽는 법**: "20%의 사진에 대해 '다시 찍어주세요'라고 하면
나머지 80%에서의 오답률이 28% → 15%로 절반이 된다."

이게 합리적인 트레이드오프인지는 **서비스 설계 판단**입니다:
- 너무 자주 거절하면 사용자가 짜증남
- 너무 안 거절하면 틀린 답을 많이 줌

```python
thr = calibrate.suggest_abstain_threshold(probs, y, max_risk=0.20)
```

"오답률 20% 이하를 유지하면서 최대한 많이 답하는 임계값"을 찾아줍니다.

### 1단계(정상/이상) 임계값은 별도

여기서는 오답률이 아니라 **recall** 을 먼저 고정합니다.

```python
evaluate.binary_report(scores, y_bin, target_recall=0.95)
```

미탐(병변인데 정상이라 함)의 비용이 오탐보다 훨씬 크기 때문입니다.

세 가지를 조합하면 이렇게 됩니다:

```python
if max_prob < abstain_threshold:

```

## 흔한 오해 3가지

**❌ "softmax 출력이 곧 확률이다"**
아닙니다. softmax 는 합이 1인 점수일 뿐, 보정된 확률이 아닙니다.
이 오해가 이 문서를 쓴 이유입니다.

**❌ "보정하면 정확도가 올라간다"**
안 올라갑니다. 순위가 안 바뀌니까요. **확률의 정직함**만 개선됩니다.
정확도가 바뀌었다면 뭔가 잘못된 겁니다.

**❌ "T 를 한 번 구하면 영원히 쓸 수 있다"**
모델을 재학습하면 T 도 다시 구해야 합니다.
데이터 분포가 바뀌어도(다른 병원, 다른 계절) 재보정이 필요합니다.
`temperature.json` 을 체크포인트 폴더에 같이 저장하는 이유입니다.
