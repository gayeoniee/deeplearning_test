## 과적합은 이미 아시죠

머신러닝에서 보신 것과 개념은 완전히 같습니다.
다만 딥러닝에서는 **훨씬 쉽게 일어납니다.** 파라미터가 수천만 개니까요.

ConvNeXt-base 는 파라미터가 **8,800만 개**입니다.
우리 학습 데이터가 3만 장이라면, 파라미터가 데이터보다 **3천 배** 많습니다.
그냥 통째로 외울 수 있는 용량입니다.

```
train macro-F1 0.98  /  val macro-F1 0.61
→ 데이터를 외웠지 규칙을 배운 게 아님
```

## 대응 수단 4가지

| 수단 | 효과 | 이 프로젝트 기본값 |
|---|---|---|
| **데이터 증강** | 가장 강력 | RandomResizedCrop + flip + 약한 색상 |
| **Dropout / DropPath** | 중간 | 0.2 / 0.1 |
| **Weight decay** | 약함 | 0.05 |
| **조기 종료** | 필수 | patience=5 |

**우선순위는 데이터 증강입니다.** 나머지는 보조입니다.

## 데이터 증강 — 이 프로젝트의 핵심 주의사항

증강은 원본 하나를 조금씩 바꿔 여러 장처럼 쓰는 기법입니다.

```
같은 사진을 좌우 뒤집고 / 살짝 회전하고 / 일부만 확대하면
모델 입장에서는 매번 다른 이미지 → 외우기 어려워짐 → 일반화
```

### ⚠️ 그런데 여기엔 함정이 있습니다

> **증강은 "라벨이 변하지 않는" 변형이어야 합니다.**

일반 이미지 분류에서는 이게 쉽습니다. 고양이를 뒤집어도 고양이니까요.

**피부 병변은 다릅니다. 색과 질감이 곧 라벨입니다.**

| 클래스 | 판단 근거 | 위험한 증강 |
|---|---|---|
| A3 태선화·**과다색소침착** | **어두운 색** | 밝기·색조 증강 → A1처럼 보임 |
| A2 비듬·**각질** | **미세 질감** | 블러·다운스케일 → 질감 소실 |
| A4 **농포** | 노란 고름 색 | 채도 증강 → 다른 병변처럼 |
| A5 미란·**궤양** | 붉은 노출면 | 색조 회전 → 완전히 다른 병변 |

일반 레시피의 `ColorJitter(brightness=0.4, contrast=0.4, saturation=0.4, hue=0.1)` 를
그대로 쓰면 **증강이 라벨을 파괴합니다.** 모델에게 거짓말을 가르치는 셈이죠.

### 그래서 우리 기본값은 의도적으로 약합니다

```python
# src/config.py
color_jitter: float = 0.1      # 일반적으로는 0.4
hue_jitter:   float = 0.02     # 일반적으로는 0.1  ← 색조는 특히 조심
vflip:        float = 0.0      # 피부 사진은 위아래 뒤집기가 부자연스러움
rotate_deg:   int   = 15       # 과하지 않게
rrc_scale:    tuple = (0.7, 1.0)   # 70% 미만으로 자르면 병변이 잘려나감
```

### 안전한 증강 vs 위험한 증강

```
✅ 안전
   좌우 뒤집기          — 피부에 좌우 방향성 없음
   ±15° 회전           — 촬영 각도 차이를 흉내
   RandomResizedCrop   — 거리 차이를 흉내 (단, scale 0.7 이상)
   약한 밝기/대비 (0.1) — 조명 차이를 흉내
   RandomErasing       — 털에 가려진 상황을 흉내

⚠️ 조심
   강한 색상 증강       — 라벨 파괴
   색조(hue) 회전      — 라벨 파괴
   Grayscale          — 색 정보가 라벨인데 통째로 삭제
   강한 블러           — A2 질감 소실

❌ 금지
   상하 뒤집기 (선택)   — 그림자·중력 단서가 부자연스러워짐
   Cutout 크게         — 병변 자체를 지울 수 있음
   MixUp (논쟁적)      — 존재하지 않는 병변 조합 생성
```

### 반드시 눈으로 확인하세요

노트북 03에 이 셀이 있습니다:

```python
x, y = next(iter(dl_tr))
# 정규화를 되돌려서 실제로 모델이 보는 이미지를 표시
```

**병변이 잘려 나갔거나, 색이 심하게 변했다면 증강이 너무 센 겁니다.**
이건 숫자로는 안 보입니다.

## Mixup / CutMix — 켤까 말까

```
Mixup:  이미지 A 70% + 이미지 B 30% 를 섞고, 라벨도 0.7/0.3 으로
CutMix: 이미지 A 에 이미지 B 의 사각형 조각을 붙이고, 면적 비율로 라벨
```

일반 이미지 분류에서는 강력합니다. **의료 이미지에서는 논쟁적입니다.**

- 반대: 실제로 존재하지 않는 병변 조합을 만들어 모델을 혼란시킴
- 찬성: 강한 정규화 효과로 과적합이 심한 경우 도움

**답은 데이터마다 다릅니다. 실험으로 정하세요.**

```python
cfg = CFG(mixup_alpha=0.0)   # 기본: 끔
cfg = CFG(mixup_alpha=0.2)   # 실험: 켬
```

노트북 04에 비교 셀이 준비되어 있습니다.

## Dropout / DropPath

```python
cfg = CFG(drop_rate=0.2, drop_path_rate=0.1)
```

- **Dropout**: 뉴런 20%를 랜덤하게 끔
- **DropPath (Stochastic Depth)**: 층 전체를 10% 확률로 건너뜀

깊은 모델(ConvNeXt, ViT)에서는 DropPath 가 더 효과적입니다.

**조정 가이드**: 과적합이 심하면 `drop_path_rate` 를 0.1 → 0.2 → 0.3 으로.
학습 자체가 안 되면 낮추세요.

## 클래스 불균형 — 정규화와 다른 문제

과적합과 별개지만 함께 다뤄야 하는 문제입니다.

```
A2: 12,000장  (40%)
A5:    900장  (3%)     ← 13배 차이
```

이대로 학습하면 모델이 "A2 라고 찍으면 대충 맞네" 를 학습합니다.

### 대응 2가지 (둘 중 **하나만** 쓰세요)

```python
cfg = CFG(balance_strategy="class_weight")       # ① 손실에 가중치
cfg = CFG(balance_strategy="weighted_sampler")   # ② 희소 클래스를 자주 뽑기
```

둘 다 쓰면 **보정이 이중으로** 걸려 희소 클래스가 과대평가됩니다.

**우리 기본값은 `class_weight`** 이고, 가중치는 `1/√n` 을 씁니다:

```python
w = 1.0 / np.sqrt(counts)    # 1/n 은 너무 공격적
```

`1/n` 을 쓰면 900장짜리 클래스에 13배 가중치가 붙어 학습이 불안정해집니다.
`1/√n` 은 3.6배 정도로 완만합니다.

### Focal Loss (선택)

```python
cfg = CFG(focal_gamma=2.0)
```

쉬운 샘플의 기여를 줄여 어려운 샘플에 집중합니다.
불균형이 아주 심할 때(50배 이상) 시도해볼 만합니다. 만능은 아닙니다.

## 진단 흐름도

```
val 성능이 나쁘다
   │
   ├─ train 도 나쁘다 (둘 다 낮음)
   │     → 과소적합. 모델을 키우거나 lr/epochs 를 늘리세요
   │     → 또는 데이터/라벨이 잘못됐는지 확인 (더 흔한 원인)
   │
   └─ train 은 좋은데 val 만 나쁘다
         → 과적합. 순서대로:
            1. 증강 강화 (단, 라벨 파괴 주의)
            2. drop_path_rate ↑
            3. 더 작은 모델
            4. 데이터 늘리기 (가장 확실)
            5. 조기 종료 앞당기기
```

> ⚠️ **그런데 먼저 의심할 것**: val 이 유독 나쁘면
> **데이터 누수가 아니라 반대로, 분할이 제대로 돼서 진짜 성능이 드러난 것**일 수 있습니다.
> 이전에 0.95 였던 게 개체 분할 후 0.72 가 됐다면, 0.72 가 진짜입니다.

## 흔한 오해 3가지

**❌ "증강은 무조건 많이 넣을수록 좋다"**
라벨을 파괴하는 증강은 성능을 **떨어뜨립니다.**
이 프로젝트에서는 특히 색상 증강을 조심하세요.

**❌ "검증 데이터에도 증강을 넣어야 공평하다"**
아닙니다. 검증은 항상 결정론적이어야 합니다.
안 그러면 돌릴 때마다 점수가 달라져 비교가 불가능합니다.

**❌ "과적합이면 무조건 모델을 줄여야 한다"**
증강과 정규화를 먼저 시도하세요. 큰 모델 + 강한 정규화가
작은 모델보다 나은 경우가 많습니다.
