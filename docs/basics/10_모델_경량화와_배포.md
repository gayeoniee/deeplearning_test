# 10. 모델 경량화와 배포

> **읽는 시점**: 학습이 끝나고 실제로 쓸 방법을 고민할 때
> **참고**: 이 프로젝트의 필수 단계는 아닙니다. 서비스로 만들 때 읽으세요.

---

## 문제 상황

학습은 끝났습니다. `best.pt` 가 350MB 입니다.

- 사용자 폰에 넣기엔 큽니다
- 서버에 올리면 GPU 인스턴스 비용이 나갑니다
- 추론 한 번에 200ms 걸리면 앱이 답답합니다

---

## 선택지 3가지

### ① 서버 추론 (가장 쉬움)

```
폰 → 사진 업로드 → 서버(GPU) → 결과 반환
```

- ✅ 구현 간단, 모델 교체 자유로움
- ✅ 큰 모델·앙상블 가능
- ❌ 서버 비용 (GPU 인스턴스는 비쌉니다)
- ❌ 네트워크 필요
- ❌ **사진이 서버로 전송됨** → 개인정보 정책 필요

**언제**: MVP, 사용자 적을 때, 정확도가 최우선일 때

### ② 온디바이스 추론

```
폰 안에서 직접 실행 (Core ML / TFLite / ONNX Runtime Mobile)
```

- ✅ 서버 비용 0
- ✅ 오프라인 동작
- ✅ **사진이 폰을 안 떠남** — 프라이버시 측면에서 큰 장점
- ❌ 모델 크기·속도 제약 (20MB 이하 권장)
- ❌ 업데이트가 앱 배포에 묶임

**언제**: 사용자 많을 때, 프라이버시가 중요할 때

### ③ 하이브리드

작은 모델로 폰에서 1차 판단 → 애매하면 서버의 큰 모델로.
우리의 **거절(abstention) 설계와 잘 맞습니다.**

---

## 경량화 기법

### 1) 애초에 작은 모델 선택

가장 확실한 방법입니다.

| 모델 | 파라미터 | 크기(fp32) | 비고 |
|---|---|---|---|
| MobileNetV4 | 4M | 16MB | 모바일 전용 설계 |
| EfficientNetV2-S | 21M | 85MB | 성능/크기 균형 좋음 |
| ConvNeXt V2 tiny | 29M | 115MB | |
| ConvNeXt V2 base | 89M | 350MB | 서버용 |

노트북 04에서 EfficientNetV2-S 가 base 모델과 macro-F1 차이가
0.02 이내라면, **작은 쪽을 고르는 게 실무적으로 옳습니다.**

### 2) 양자화 (Quantization)

가중치를 float32 → int8 로 바꿉니다.

```
크기 1/4, 속도 2~4배, 정확도 손실 보통 1%p 미만
```

```python
# 동적 양자화 (가장 간단, CPU 추론용)
import torch
qmodel = torch.quantization.quantize_dynamic(
    model, {torch.nn.Linear}, dtype=torch.qint8
)
```

더 좋은 방법은 **QAT(Quantization-Aware Training)** — 학습 중에 양자화를
시뮬레이션해서 손실을 줄입니다. 손이 더 가지만 정확도가 잘 유지됩니다.

> ⚠️ 양자화 후 **반드시 재평가**하세요. 특히 우리처럼 확률 보정이 중요한
> 경우, 양자화가 확률 분포를 미묘하게 바꿔 **T 를 다시 구해야** 할 수 있습니다.

### 3) 지식 증류 (Knowledge Distillation)

큰 모델(teacher)의 출력을 작은 모델(student)이 흉내내게 학습시킵니다.

```
teacher: ConvNeXt V2 base (macro-F1 0.76)
              ↓ 소프트 라벨로 가르침
student: EfficientNetV2-S (0.72 → 0.75)
```

**정답 라벨보다 teacher 의 확률 분포가 더 많은 정보를 담습니다.**
"이건 A5인데 A6일 가능성도 25%" 같은 뉘앙스까지 전달되거든요.

앙상블을 단일 모델로 압축할 때 특히 유용합니다.

### 4) 프루닝 (Pruning)

중요도가 낮은 연결을 잘라냅니다. 이론적으로 매력적이지만
실제 속도 향상은 하드웨어 지원에 달려 있어서 기대만큼 안 나오는 경우가 많습니다.
우선순위는 낮습니다.

## ONNX 로 내보내기

프레임워크 독립 포맷입니다. 배포의 표준 경로입니다.

```python
import torch

model.eval()
dummy = torch.randn(1, 3, 288, 288)

torch.onnx.export(
    model, dummy, "dogskin.onnx",
    input_names=["image"], output_names=["logits"],
    dynamic_axes={"image": {0: "batch"}, "logits": {0: "batch"}},
    opset_version=17,
)
```

```python
# 추론
import onnxruntime as ort
sess = ort.InferenceSession("dogskin.onnx")
logits = sess.run(None, {"image": arr})[0]
```

**ONNX 에서 갈라지는 길:**
- iOS → Core ML (`coremltools`)
- Android → TFLite (`onnx2tf`) 또는 ONNX Runtime Mobile
- 서버 → ONNX Runtime, TensorRT

> ⚠️ **내보낸 뒤 원본과 출력이 같은지 반드시 확인하세요.**
> ```python
> assert np.allclose(torch_out, onnx_out, atol=1e-4)
> ```
> 미묘한 연산 차이로 결과가 달라지는 경우가 있습니다.

## 전처리를 잊지 마세요

**가장 흔한 배포 버그**입니다.

```
학습:  Resize(328) → CenterCrop(288) → ToTensor → Normalize(ImageNet)
배포:  Resize((288,288)) → /255
                          ^^^^^^^^^ Normalize 누락, 종횡비 왜곡
```

모델은 멀쩡한데 **실서비스에서만 성능이 반토막** 납니다. 그리고 원인을 못 찾습니다.

**대책**: 전처리 설정을 모델과 **함께** 저장하세요.

```python
# 우리 체크포인트는 cfg 를 함께 저장합니다
ck = torch.load("best.pt", weights_only=False)
print(ck["cfg"]["img_size"])   # 288
print(ck["classes"])           # ['A1','A2',...]  ← 순서도 중요!
```

`infer.Engine.load()` 가 이걸 자동으로 복원합니다.

## 배포에 반드시 포함해야 할 것

우리 프로젝트에서는 모델 가중치만 배포하면 **안 됩니다.**

```
필수 패키지:
├── model.onnx           가중치
├── config.json          img_size, mean, std, 클래스 순서
├── temperature.json     보정 온도 T          ← 빠뜨리기 쉬움
├── thresholds.json      거절 임계값, 1단계 임계값
└── messages.py          출력 문구 템플릿
```

`temperature.json` 이 빠지면 보정 안 된 확률이 사용자에게 노출됩니다.
그건 [문서 08](08_확률보정과_임계값_결정.md)에서 말한 "거짓말"입니다.

## 추론 속도 최적화

```python
model.eval()
with torch.inference_mode():        # no_grad 보다 조금 더 빠름
    logits = model(x)
```

| 기법 | 효과 |
|---|---|
| `torch.inference_mode()` | 소폭 |
| 배치 처리 | 큼 (여러 장 동시에) |
| `channels_last` 메모리 포맷 | CNN 에서 소폭 |
| `torch.compile()` | 1.2~2배 (PyTorch 2.x) |
| ONNX Runtime | 1.5~3배 |
| **TTA 끄기** | 2배 (hflip TTA 는 추론이 2배) |

> 💡 TTA 는 정확도를 조금 올리지만 추론이 2배 느려집니다.
> 서비스에서는 **끄는 게** 나을 수 있습니다. 정확도 이득을 재보고 결정하세요.

## 모니터링 — 배포가 끝이 아닙니다

배포 후에 반드시 봐야 할 것:

1. **입력 분포 변화** — 학습 데이터는 병원 사진, 실제는 보호자 스마트폰.
   조명·초점·거리가 다릅니다. 성능이 떨어질 수밖에 없습니다.
2. **거절 비율** — 갑자기 늘면 입력 품질이 나빠졌거나 모델이 낯선 걸 보고 있는 것
3. **클래스별 예측 분포** — 한 클래스로 쏠리면 이상 신호
4. **사용자 피드백** — 가능하면 "실제 진단 결과" 를 수집

> ⚠️ 사용자 사진을 재학습에 쓰려면 **명시적 동의**가 필요합니다.
> 개인정보 처리방침에 반드시 포함하세요.

## 실전 체크리스트

- [ ] ONNX 출력이 PyTorch 와 일치 (`allclose`)
- [ ] 전처리(img_size, mean, std)가 학습과 동일
- [ ] 클래스 순서가 학습과 동일
- [ ] temperature.json 포함
- [ ] 거절 임계값 포함
- [ ] 면책 문구가 모든 출력에 포함
- [ ] 양자화했다면 재평가 + 재보정 완료
- [ ] 모니터링 지표 설정
