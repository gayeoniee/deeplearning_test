# ⚠️ 09 — 세션이 끊겼을 때 (Colab / Kaggle)

> 한 줄 요약: **노트북을 위에서부터 그냥 다시 돌리세요.** 끝난 학습은 건너뛰고,
> 끊긴 학습은 그 에폭부터 이어갑니다. 조건은 하나 — **Drive 마운트**.

---

## 왜 위험한가

Colab 의 `/content` 는 **세션 저장소**입니다. 세션이 끊기면 통째로 사라집니다.
"끊긴다" 는 다음을 다 포함합니다:

| 원인 | 얼마나 자주 |
|---|---|
| 90분 무조작 → 유휴 종료 | 흔함 (학습 중에도 브라우저 탭을 닫으면) |
| 12시간(무료는 더 짧음) 최대 실행시간 초과 | 긴 학습에서 |
| GPU 사용량 한도 초과 | 무료 티어에서 흔함 |
| 브라우저/네트워크 끊김 | 자주 |
| OOM / 디스크 부족으로 런타임 강제 종료 | 배치를 키웠을 때 |

우리 프로젝트에서 잃는 것:

```
/content/data/work/crops/        45,885장   ← zip 에서 다시 풀면 됩니다 (몇 분)
/content/data/work/manifests/    매니페스트  ← 같은 zip 안에 있습니다
/content/data/work/checkpoints/  체크포인트  ← 🚨 다시 만들려면 GPU 1시간 반
```

**체크포인트만 문제입니다.** 나머지는 Drive 의 `dogskin_prepared.zip` 에서 복구됩니다.

---

## 어떻게 막았나

`src/train.py` 가 매 에폭 두 가지를 합니다.

### 1) `last.pt` — 이어받기용 전체 상태

```
model        가중치
ema          지수이동평균 가중치 (평가·best 저장에 쓰는 쪽)
optimizer    AdamW 모멘텀 (exp_avg, exp_avg_sq)
scheduler    cosine 스케줄의 현재 위치
scaler       fp16 GradScaler 스케일
rng          torch / cuda / numpy / python 난수 상태
epoch, best, bad_epochs, history, elapsed_sec
```

옵티마이저 모멘텀이 빠지면 이어받은 직후 몇십 스텝 동안 학습이 흔들립니다.
그래서 가중치만 저장하는 걸로는 부족합니다.

### 2) 그걸 세션 밖으로 복사

`env.persist_root()` 가 살아남는 위치를 정합니다:

| 환경 | 위치 |
|---|---|
| Colab (Drive 마운트됨) | `/content/drive/MyDrive/dogskin_work` |
| Colab (마운트 안 함) | **None → 보호 없음** 🚨 |
| Kaggle | `/kaggle/working` (세션 출력으로 보존됨) |
| 로컬 | `work_root()` — 애초에 휘발성이 아님 |
| 직접 지정 | 환경변수 `DOG_SKIN_PERSIST` |

복사는 `.tmp` 로 쓰고 이름을 바꾸는 방식입니다. 복사 도중에 끊겨도
**반쪽짜리 체크포인트가 남지 않습니다.**

## 끊긴 다음에 할 일

노트북을 처음 셀부터 다시 실행합니다. 그게 전부입니다.

```
1번 셀   리포 재동기화 + 패키지 설치         2~3분
0-b 셀   Drive 마운트 + zip 재해제           3~5분
1번      감사 / 하한선                        5분   (다시 계산, 결과 동일)
3번      1단계 학습    ⏭️ 또는 ▶️
4번      2단계 학습    ⏭️ 또는 ▶️
5~7번    평가 · 저장                          10분
```

학습 셀이 찍는 메시지로 무슨 일이 벌어졌는지 알 수 있습니다:

| 메시지 | 뜻 |
|---|---|
| `⏭️ '...' 은 이미 끝난 학습입니다 — 건너뜁니다.` | 학습 0초. best 가중치만 모델에 얹음 |
| `▶️ '...' 을 epoch 17 부터 이어서 합니다` | 앞의 17에폭은 다시 안 함 |
| `🔁 '...' 을 12 → 25 에폭으로 연장합니다` | `epochs` 를 늘려서 다시 부른 경우 |
| `🆕 처음부터` (`print_status`) | 이 실험의 기록이 없음 |
| `⚠️ 중단 대비 백업 없음` | 🚨 Drive 마운트를 안 했습니다. 지금 멈추세요 |

### 의도적으로 다시 학습하려면

```python
train.fit(m2, dl_tr2, dl_va2, cfg2, ds_train=ds_tr2, resume=False)
```

`resume=False` 는 `history.csv` / `last.pt` / `result.json` 을 지우고 처음부터 갑니다.
(`best.pt` 는 새 best 가 나올 때 덮어씁니다)

### 더 돌려보고 싶으면

`cfg.epochs` 만 올려서 같은 `exp_name` 으로 다시 부르면 **이어서 연장**합니다.
25에폭까지 돌렸는데 계속 좋아지고 있었다면 40으로 올리세요 — 앞의 25는 다시 안 합니다.

> ⚠️ 단, **조기 종료로 끝난 학습은 연장하지 않습니다.** patience 를 넘겨 멈춘 건
> "더 돌려도 안 좋아진다" 는 결론이므로, `epochs` 를 올려도 건너뜁니다.
> 정말 더 돌리려면 `early_stop_patience` 를 늘리고 `resume=False` 로 다시 하세요.

## 비용 — Drive 용량과 시간

실험 하나당:

| 파일 | 크기 (ResNet50) | 언제 씀 |
|---|---|---|
| `best.pt` | ~200MB (model + ema) | 점수가 갱신될 때만 |
| `last.pt` | ~400MB (+ optimizer) | 매 에폭 |
| `history.csv`, `result.json`, `config.json` | 수 KB | 매 에폭 |

- 노트북 03 은 실험 2개 = **약 1.2GB**
- 노트북 04 는 모델 6개 = **약 3.6GB** (백본이 크면 더)
- Drive 쓰기가 에폭당 10~30초 붙습니다. 학습 로그의 `| 백업 12초` 가 그 값입니다.

에폭당 3분 학습에 20초 백업 = **11% 오버헤드**.
80분을 날리는 것보다 싸다는 판단입니다. 그래도 아깝다면:

```python
train.fit(..., persist_every=3)   # 3에폭마다 백업 → 최대 2에폭만 되돌아감
train.fit(..., persist=False)     # 백업 끔 (로컬 PC 에서 돌릴 때)
```

용량이 부족하면 학습이 끝난 실험의 `last.pt` 를 지우세요.
`best.pt` 만 있으면 평가·추론은 다 됩니다 (이어받기만 못 함).

```
Drive/dogskin_work/checkpoints/*/last.pt   ← 삭제 가능
```

## 이어받은 학습은 처음부터 돌린 것과 완전히 같은가

**아닙니다.** 정직하게 적어둡니다.

같은 것: 가중치, 옵티마이저 모멘텀, 스케줄러 위치, EMA, 난수 상태.

다른 것: **DataLoader 가 배치를 섞는 순서**입니다. `DataLoader` 는 에폭마다
워커 프로세스를 새로 만들고 자기 시드로 순서를 정하는데, 그 내부 상태까지는
저장하지 않았습니다. 그래서 이어받은 에폭의 배치 순서는 원래와 다릅니다.

영향: 최종 점수가 소수점 셋째 자리에서 흔들릴 수 있습니다.
논문 재현이 목적이면 문제지만, 우리는 "실측 기준선과 개선폭을 본다" 는 목적이라
수용 가능합니다. **정확히 재현해야 하는 실험은 끊기지 않게 한 번에 돌리세요.**

## Kaggle 은 어떻게 다른가

- `/kaggle/working` 은 **커밋(Save Version) 하면** 출력으로 보존됩니다.
  세션이 끊긴 뒤 다음 세션에서 그 출력을 Input 으로 붙여야 읽힙니다.
- 대화형 세션은 9시간, GPU 주당 30시간 한도가 있습니다.
- `persist_root()` 는 Kaggle 에서 `/kaggle/working` 을 돌려주므로 코드는 그대로 돕니다.
  다만 **세션을 커밋하지 않으면 그것도 사라집니다** — Colab + Drive 쪽이 더 안전합니다.
