## 한 줄 요약

**같은 강아지 사진이 학습셋과 검증셋에 나뉘어 들어가면, 정확도 숫자가 거짓말을 합니다.**

---

## 왜 하필 이 데이터에서 위험한가

AI Hub 561 데이터는 이런 규모입니다:

```
반려동물 약 10,000 마리  →  이미지 500,000 장 이상
                            = 개체당 평균 50장
```

한 마리의 강아지를 **각도만 바꿔가며 수십 장** 찍었다는 뜻입니다.
같은 개, 같은 부위, 같은 병변, 같은 조명, 같은 진료대. 사진만 다릅니다.

이제 흔히 하는 실수를 봅시다:

```python
# ❌ 절대 하면 안 되는 분할
from sklearn.model_selection import train_test_split
train, val = train_test_split(df, test_size=0.2, stratify=df["label"])
```

머신러닝에서는 이게 정석이죠. 여기서는 **재앙**입니다.

같은 강아지의 50장 중 40장은 train, 10장은 val 로 갈립니다.
모델은 병변을 배우는 대신 **"아, 이 갈색 털에 파란 진료대 = A3"** 를 외웁니다.
그리고 val 에서 그 강아지를 또 만나니까 다 맞힙니다.

**검증 정확도 95%. 실제 처음 보는 강아지에서는 60%.**

---

## 이게 왜 다른 버그보다 나쁜가

보통 버그는 에러를 냅니다. 이건 아닙니다.

| | 일반 버그 | 데이터 누수 |
|---|---|---|
| 증상 | 코드가 멈춤 | **코드가 잘 돌아감** |
| 지표 | 나빠짐 | **좋아짐** 🎉 |
| 발견 시점 | 즉시 | **배포 후** |
| 기분 | 짜증 | 성공한 줄 알았는데... |

누수는 스스로를 **성공처럼** 위장합니다.
"와 macro-F1 0.94 나왔다!" 하고 기뻐하는 순간이 가장 위험한 순간입니다.

> 💡 **경험칙**: 이 데이터로 개체 단위 분할을 했는데 macro-F1 이 0.95 넘게 나왔다면,
> 축하할 게 아니라 **분할을 의심하세요.**

## 이 프로젝트의 방어선 3겹

### 1겹: 개체ID로 그룹 분할

`src/split.py` 가 `animal_id` 기준으로 나눕니다.
한 강아지의 사진은 **전부 train 이거나 전부 val**, 절대 섞이지 않습니다.

```python
from sklearn.model_selection import StratifiedGroupKFold
skf = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)
skf.split(X, y, groups=animal_id)   # ← groups 가 핵심
```

`StratifiedGroupKFold` 는 두 가지를 동시에 합니다:
- **Group**: 같은 개체는 안 나뉨
- **Stratified**: 클래스 비율은 fold 마다 비슷하게

### 2겹: 중복 클러스터도 그룹에 포함

개체ID가 다르게 기록됐지만 **사실상 같은 사진**인 경우가 있습니다.
`src/dedup.py` 가 phash 로 찾아낸 중복 클러스터를 개체ID와 **union-find 로 합칩니다.**

```
animal_id = "D001" ─┐
                    ├─→ 같은 그룹 G000042
dup_cluster = 17 ───┘
```

개체ID 추출이 실패해도 중복 클러스터가 최소한의 방어선이 됩니다.

### 3겹: assert 로 강제 검증

```python
split.verify(df, fold=0)   # 겹치면 AssertionError
```

train/val/holdout 사이에 그룹·개체·해시가 하나라도 겹치면 **에러를 냅니다.**
경고가 아니라 에러입니다. 조용히 넘어가면 안 되는 문제라서요.

## 직접 확인해보기

`src/split.py` 에 비교 함수를 넣어뒀습니다:

```python
split.compare_with_random(df)
```

출력 예시:
```
[참고] 만약 이미지 단위로 무작위 분할했다면:
  train/val 이 공유하는 그룹: 29개
  val 이미지 중 train 에 같은 개체가 있는 비율: 100.0%
  → 이 비율만큼 검증 점수가 부풀려집니다.
```

**val 의 100%가 오염**됐다는 뜻입니다. 그 상태의 정확도는 아무 의미가 없습니다.

## 다른 형태의 누수들 (이것도 조심)

### 전처리를 분할 **전에** 하기

```python
# ❌ 정규화 통계를 전체 데이터로 계산
mean = df["feature"].mean()          # val 정보가 train 에 샘
train, val = split(df)

# ✅ train 으로만 계산해서 val 에 적용
train, val = split(df)
mean = train["feature"].mean()
```

이 프로젝트에서는 ImageNet 사전학습 통계를 쓰므로 이 문제는 없습니다.
하지만 나중에 직접 통계를 낼 일이 생기면 기억하세요.

### 중복 제거를 분할 **후에** 하기

순서가 뒤집히면 이미 나뉜 뒤라 같은 사진이 양쪽에 남습니다.
그래서 `02_전처리` 노트북 순서가 **중복 제거 → 분할** 입니다.

### holdout 을 여러 번 보기

```python
ho = split.get_holdout(df)
# 결과 보고 → 하이퍼파라미터 수정 → 다시 holdout 확인 → ...
```

이러면 holdout 은 사실상 검증셋이 됩니다.
**모든 결정이 끝난 뒤 딱 한 번**만 여세요.

### TTA/앙상블 결정을 테스트셋 보고 하기

"TTA 켜니까 holdout 이 올라가네, 켜자" — 이것도 누수입니다.
그런 결정은 검증셋에서 하세요.

## 체크리스트

전처리를 끝냈다면 아래를 전부 통과해야 합니다:

- [ ] `split.verify(df, fold)` 가 에러 없이 통과
- [ ] 개체당 평균 이미지 수가 1.5 이상 (1에 가까우면 개체ID 추출 실패)
- [ ] `dedup.run()` 에서 라벨 충돌 중복을 제거함
- [ ] 중복 제거 → 분할 순서를 지킴
- [ ] holdout 은 아직 한 번도 안 열어봄
