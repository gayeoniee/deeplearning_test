# ⚠️ 실험 기록과 재현성

> **읽는 시점**: 두 번째 실험을 돌리기 전에.

---

## 이 문서가 필요한 이유

딥러닝 실험은 금방 이렇게 됩니다:

```
best_model.pt
best_model_v2.pt
best_model_v2_final.pt
best_model_v2_final_진짜최종.pt      ← 이게 뭐로 학습한 거였지?
```

머신러닝보다 훨씬 심합니다. 학습에 몇 시간씩 걸려서 **다시 돌려볼 수가 없거든요.**
"그때 그 0.78 은 어떤 설정이었지?" 를 못 찾으면 그 실험은 없었던 것과 같습니다.

## 이 프로젝트가 자동으로 남기는 것

`train.fit()` 을 부르면 `work/checkpoints/{exp_name}/` 아래에 자동 생성됩니다:

```
work/checkpoints/zoo_convnextv2_base/
├── config.json      ← 모든 하이퍼파라미터 (CFG 전체)
├── history.csv      ← 에폭별 loss / acc / macro_f1 / lr
├── best.pt          ← 가중치 + EMA + 그때의 cfg + 클래스 목록
└── result.json      ← 최고 점수, 최고 에폭, 소요 시간
```

**`best.pt` 안에 cfg 가 들어 있습니다.** 나중에 체크포인트만 있어도
어떤 설정이었는지 복원할 수 있습니다:

```python
import torch
ck = torch.load("best.pt", map_location="cpu", weights_only=False)
print(ck["cfg"])        # 그때의 전체 설정
print(ck["classes"])    # 클래스 순서 (중요!)
print(ck["score"], ck["epoch"])
```

## 규칙 1 — 하이퍼파라미터를 노트북에 쓰지 마세요

```python
# ❌ 노트북 셀에 흩어놓기
lr = 3e-4
epochs = 20
img_size = 384
```

이러면 노트북을 다시 실행할 때 어떤 셀을 고쳤는지 기억이 안 납니다.

```python
# ✅ CFG 하나로
cfg = CFG(lr=3e-4, epochs=20, img_size=384, exp_name="convnext_lr3e4")
```

`CFG` 는 `config.json` 으로 통째로 저장되고 `CFG.load()` 로 되살아납니다.

## 규칙 2 — exp_name 을 성의 있게

```python
exp_name = "exp1"              # ❌ 일주일 뒤 아무 의미 없음
exp_name = "convnextv2_m1.5_ep15_mixup"   # ✅ 이름만 봐도 알 수 있음
```

권장 형식: `{모델}_{크롭}_{핵심변경}`

이름이 같으면 **덮어씁니다.** 비교 실험은 반드시 이름을 다르게.

## 규칙 3 — 한 번에 하나만 바꾸기

```
실험 A: convnextv2 + m1.5 + mixup 없음  → 0.74
실험 B: eva02     + m2.5 + mixup 있음  → 0.71
```

이러면 **뭐 때문에 떨어졌는지 알 수 없습니다.** 모델? 크롭? mixup?

한 번에 하나씩:
```
A: convnextv2 + m1.5 + no mixup  → 0.74   (기준)
B: convnextv2 + m2.5 + no mixup  → 0.71   ← 크롭 효과
C: convnextv2 + m1.5 + mixup     → 0.76   ← mixup 효과
```

노트북 03의 크롭 비교 실험이 이 원칙을 따릅니다.

---

## 규칙 4 — 시드를 고정하되, 맹신하지 마세요

```python
env.set_seed(42)
```

시드를 고정해도 GPU 연산은 완전히 결정론적이지 않습니다
(cuDNN 알고리즘 선택, atomic 연산 순서 등).

**완전 재현이 필요하면:**
```python
env.set_seed(42, deterministic=True)   # 느려집니다
```

**더 중요한 것**: 시드 하나의 결과를 믿지 마세요.
0.74 vs 0.76 차이는 시드만 바꿔도 나올 수 있습니다.

```python
# 진짜 차이인지 확인
for seed in [42, 1337, 2024]:
    cfg = CFG(seed=seed, exp_name=f"convnext_s{seed}")
    ...
```

또는 이 프로젝트가 제공하는 **부트스트랩 신뢰구간**을 쓰세요:

```
macro-F1: 0.7412 (95% CI 0.7103 – 0.7698)
```

CI 가 겹치는 두 모델은 "다르다"고 말할 수 없습니다.

## 규칙 5 — 실패한 실험도 기록

```
❌ eva02_base 384px  → OOM. T4 에서 안 됨. 224px 로 내리면 가능
❌ color_jitter 0.4  → macro-F1 0.68 로 하락. A3 가 특히 망가짐
❌ mixup 0.4         → 0.71. 0.2 보다 나쁨
```

이게 없으면 **3주 뒤에 같은 실험을 또 합니다.**
`docs/` 아래에 `실험로그.md` 를 만들어 한 줄씩 쌓으세요.

## 결과표 관리

여러 실험을 비교할 땐:

```python
from src import evaluate
evaluate.compare_models({"resnet50": rep_a, "convnextv2": rep_b, ...})
```

```
     model  macro_F1  CI_low  CI_high  bal_acc  accuracy  AUROC  min_recall
convnextv2    0.7612  0.7301   0.7889   0.7455    0.7801 0.9312      0.5920
 effnetv2_s   0.7488  0.7166   0.7783   0.7301    0.7702 0.9245      0.5511
   resnet50   0.7104  0.6788   0.7412   0.6955    0.7398 0.9013      0.4802
```

**보는 순서:**
1. `min_recall` — 최악 클래스를 얼마나 놓치나 (이게 낮으면 탈락)
2. `macro_F1` + CI — 겹치면 무승부
3. `accuracy` — 참고만
