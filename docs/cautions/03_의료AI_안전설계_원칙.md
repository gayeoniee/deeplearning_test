## 우리가 만드는 것과 만들지 않는 것

| 만드는 것 ✅ | 만들지 않는 것 ❌ |
|---|---|
| "이런 형태의 병변이 **의심됩니다**" | "이 강아지는 **말라세지아 피부염입니다**" |
| "병원에 가보시는 걸 권합니다" | "이 연고를 바르세요" |
| 스크리닝 보조 (관심을 유도) | 진단 (판단을 대체) |
| 확률과 불확실성을 함께 제시 | 단일 정답 제시 |

이 구분은 말장난이 아닙니다. **법적으로도, 윤리적으로도, 기술적으로도** 다른 물건입니다.

## 1. 라벨이 병명이 아니라는 사실을 잊지 마세요

이 데이터의 A1~A6은 **병변의 형태(morphology)** 입니다. 병명이 아닙니다.

| 코드 | 병변 형태 | 이 형태를 만들 수 있는 질환들 |
|---|---|---|
| A1 | 구진·플라크 | 알레르기, 농피증, 모낭충증, 접촉성 피부염… |
| A2 | 비듬·각질·상피성잔고리 | 지루증, 말라세지아, 농피증 회복기, 갑상선 저하증… |
| A3 | 태선화·과다색소침착 | 만성 아토피, 내분비 질환, 만성 마찰… |
| A4 | 농포·여드름 | 세균성 농피증, 낙엽상 천포창, 모낭염… |
| A5 | 미란·궤양 | 자가면역 질환, 심한 감염, 외상, 종양… |
| A6 | 결절·종괴 | 양성 종양, **악성 종양**, 육아종, 낭종… |

**같은 모양이 여러 질환에서 나오고, 같은 질환이 여러 모양으로 나타납니다.**

그래서 모델이 A4를 맞혔다고 해서 "농피증"이라고 말하면 안 됩니다.
치료가 완전히 달라지니까요 — 세균성이면 항생제, 자가면역이면 면역억제제.
정반대 처방입니다.

**출력 문구 규칙**: 항상 "**~ 형태의 병변이 의심됩니다**" 까지만.

> ⚠️ **2026-08-26 에 여기서 한 칸 더 물러섰습니다.**
> 실측해 보니 그 "형태" 이름조차 절반 넘게 틀렸습니다 (holdout 56.6%).
> 그래서 2단계 파이프라인은 **형태 이름도 단정하지 않습니다** — §7-B 를 보세요.

## 2. 오류의 비용은 대칭이 아닙니다

머신러닝에서는 보통 정확도를 최대화합니다. 여기서는 아닙니다.

```
미탐 (병변인데 "정상"이라고 함)
   → 보호자가 안심 → 병원 안 감 → 진행 → 최악의 경우 악성 종양 방치

오탐 (정상인데 "의심된다"고 함)
   → 보호자가 병원 감 → 진료비 몇 만원 → "괜찮네요"
```

**비용 차이가 100배쯤 납니다.** 그래서 설계가 이렇게 됩니다:

```python
cfg.target_recall_stage1 = 0.95   # 재현율을 먼저 고정
cfg.monitor = "macro_f1"          # accuracy 아님
```

1단계(정상/이상)에서 **recall ≥ 0.95** 를 만족하는 임계값을 먼저 잡고,
그 조건에서 precision 이 얼마나 나오는지를 봅니다.
precision 이 0.4 라도 — 즉 알림 10건 중 6건이 헛걸음이라도 — 스크리닝으로는 쓸 만합니다.

특히 **A6(결절·종괴)** 는 악성 종양 감별이 필요한 병변이라 절대 놓치면 안 됩니다.
클래스별 recall 을 항상 확인하세요.

## 3. 모르면 모른다고 해야 합니다

신경망은 **무조건 답을 냅니다.** 고양이 사진을 넣어도, 초점 나간 사진을 넣어도,
바닥 사진을 넣어도 6개 중 하나를 고릅니다. 그것도 자신 있게.

그래서 **거절(abstention)** 이 필요합니다:

```python
if max_prob < cfg.abstain_threshold:
    return "판단이 어려운 사진입니다. 다시 찍어주세요."
```

임계값은 감으로 정하지 말고 `calibrate.coverage_risk_curve()` 로 정합니다:

```
답한 비율 → 오답률
   100%  →  28%
    80%  →  15%     ← 20% 를 포기하면 오답률이 절반으로
    70%  →  11%
```

"80%에만 답하고 20%는 다시 찍으라고 하기"가 합리적인 트레이드오프인지
직접 보고 결정하세요.

## 4. 확률은 정직해야 합니다

"신뢰도 72%" 라고 화면에 띄우려면, 그 72%가 **진짜 72%** 여야 합니다.

보정 안 된 신경망은 "95% 확신" 이라고 한 예측이 실제로는 70%만 맞습니다.
그 숫자를 보호자에게 보여주면 **거짓말을 하는 것**입니다.

→ 온도 스케일링 필수. `docs/basics/08_확률보정과_임계값_결정.md` 참고.

**ECE가 0.10을 넘으면 확률 숫자를 노출하지 마세요.**
대신 "높음 / 보통 / 낮음" 같은 밴드로만 보여주세요.

## 5. "정상"도 단정하지 않습니다

```
❌ "정상입니다."
✅ "뚜렷한 피부 병변 소견은 보이지 않습니다.
    다만 사진 한 장으로 확인할 수 있는 범위에는 한계가 있습니다.
    가려워하거나 냄새가 나는 등 평소와 다른 행동이 있다면
    결과와 무관하게 병원에 가보시는 것을 권합니다."
```

사진 한 장이 못 보는 것: 병변의 냄새, 촉감, 열감, 통증 반응, 전신 증상, 병력.
수의사가 보는 것의 일부만 보고 있다는 걸 **사용자에게 알려야** 합니다.

## 6. 데이터가 대표하지 못하는 것들

이 모델이 **못 보는** 것들을 알고 있어야 합니다:

| 한계 | 왜 |
|---|---|
| 촬영 조건 차이 | 학습 데이터는 병원에서 찍음. 보호자 스마트폰은 조명·초점·거리가 다름 |
| 견종 편향 | 특정 견종이 과대표집됐을 수 있음. 털 색·질감이 다르면 성능 저하 |
| 희소 질환 | 데이터에 없는 병변은 **가장 비슷한 6개 중 하나**로 답함 |
| 부위 편향 | 특정 부위(등, 배)에 데이터가 몰려 있을 수 있음 |
| 진행 단계 | 초기 병변은 데이터가 적을 가능성 |

**스캔 결과(`DATASET_CARD.md`)에서 견종·부위 분포를 꼭 확인하세요.**
편향이 크면 그 사실을 서비스 안내에 명시해야 합니다.

## 7-A. 출력 문구 규격 — 단일 모델 (`compose_message`)

⚠️ 아래는 **모델 하나만** 놓고 볼 때의 규격입니다. 실제 서비스가 쓰는
2단계 파이프라인은 §7-B 의 더 보수적인 규격을 씁니다.

`src/infer.py` 의 `compose_message()` 가 이 규격을 강제합니다:

```
🔎 **비듬·각질** 형태의 병변이 의심됩니다. (신뢰도 72%, 보통)

이건 병변의 겉모습에 대한 소견이지 병명이 아닙니다. 같은 모양이라도
원인 질환은 알레르기, 감염, 내분비 질환 등 여러 가지일 수 있고,
원인에 따라 치료가 완전히 달라집니다.

다른 가능성: 구진·플라크 15%, 농포·여드름 8%

_이 결과는 수의학적 진단이 아니며, 수의사의 진료를 대체하지 않습니다._
```

포함된 요소:
1. **"의심됩니다"** — 단정 회피
2. **신뢰도 + 밴드** — 불확실성 노출
3. **병명이 아니라는 설명** — 오해 방지
4. **상위 2~3개** — 단일 정답 회피
5. **면책 문구** — 항상, 예외 없이

## 7-B. ★ 출력 문구 규격 — 2단계 파이프라인 (`compose_screening_message`)

**확정: 2026-08-26 (멘토 피드백).** 이게 서비스가 실제로 내보내는 문구입니다.

### 왜 이름을 빼는가 — 숫자로

| 근거 | 실측 |
|---|---|
| 화면에 뜬 병변 이름이 **틀린 비율** | **56.6%** (병원 권고 4,478건 중 2,534건) |
| ├ 병변이긴 한데 이름이 틀림 | 1,301건 |
| └ 애초에 병변이 아님 (헛알림) | 1,233건 |
| A6(결절·종괴)를 A2(비듬)로 부름 | 56장 |
| A6 을 A3(태선화)로 부름 | 47장 |
| 아키텍처가 다른 두 모델의 격차 | convnextv2 0.5744 vs swinv2 0.5718 = **0.0026** |

마지막 줄이 핵심입니다. CNN 과 어텐션이라는 **완전히 다른 구조**가
0.0026 차이로 겹칩니다 — 잡음(±0.02) 안입니다. 막힌 게 모델이 아니라
데이터라는 뜻이고, 백본을 더 바꿔도 이 이름은 안 맞습니다.

그리고 틀리는 방향이 나쁩니다. **결절·종괴를 비듬이라고 부르면
보호자는 병원을 미룹니다.** §2 의 미탐 비용이 그대로 발생합니다.

### 형식

```
🔎 **피부에 이상 소견이 보입니다.** (이상 가능성 62%)

**어떤 병변인지는 이 사진만으로 판단할 수 없습니다.**
아래는 모델이 비슷하다고 본 정도이며, 진단이 아닙니다.

    비듬·각질·상피성잔고리   31%  ██████
    태선화·과다색소침착      22%  ████
    구진·플라크              18%  ████
    미란·궤양                13%  ███
    농포·여드름               9%  ██
    결절·종괴                 7%  █

→ **수의사 진료를 받아보시기를 권합니다.**

_이 결과는 수의학적 진단이 아니며, 수의사의 진료를 대체하지 않습니다._
```

### 표시 규칙 (`tests/test_screening_message.py` 가 못 박음)

1. **1등을 뽑아 굵게 쓰지 않습니다.** 굵게 쓰면 사람은 그걸 답으로 읽습니다
2. **여섯 개를 전부 보여줍니다.** 상위 2~3개로 자르면 그게 답처럼 보입니다.
   전부 보여줄 때만 "확실하지 않다" 가 눈에 보입니다
3. **클래스별 긴급도 문구(`URGENCY_HINT`)를 붙이지 않습니다** — 이름을 단정하는 셈입니다
4. **"판단할 수 없습니다" 를 숫자보다 위에** 씁니다
5. **깎기 전 원본 확률**을 띄웁니다 (합 = 1).
   `Prediction.topk` 는 1단계 확률을 곱해 낮춰둔 거절 판정용 값입니다 —
   그걸 띄우면 여섯 개가 다 작아져 분포로 안 읽힙니다.
   그래서 `Prediction.stage2_probs` 에 원본을 따로 들고 다닙니다
6. **정상 · 거절 경로는 그대로**입니다 — 정상도 단정하지 않고, 저신뢰는 재촬영 안내

### 이름을 다시 보여주려면 (되돌리는 조건)

지금은 못 보여줍니다. 아래를 **실측으로** 만족해야 재검토합니다:

- 병변 6종 macro-F1 이 잡음(±0.02) 밖에서 유의하게 올라갈 것
- 거절(abstention) 을 걸었을 때 **커버리지 50% 이상에서 오답률 ≤ 20%**
  (2026-08 현재: 오답률 20% 를 맞추려면 커버리지가 **18.2%** 까지 떨어집니다 — 미달)
- 그 커버리지 곡선은 헛알림 1,233건을 **빼고** 그린 것이라, 실제는 더 나쁩니다

## 8. 해서는 안 되는 것

- ❌ 특정 약품·연고·용법을 추천
- ❌ "지켜봐도 됩니다" 같은 **진료를 미루게 하는** 안내
- ❌ 확률 없이 라벨만 단독 출력
- ❌ 2단계 1등을 병변 이름으로 단정 (§7-B — 절반 넘게 틀립니다)
- ❌ 면책 문구를 접기·작게·회색으로 숨기기
- ❌ "수의사보다 정확" 같은 마케팅
- ❌ 사용자 사진을 동의 없이 재학습에 사용
