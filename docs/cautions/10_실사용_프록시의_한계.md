# 10 · 실사용 사진이 없을 때 우리가 쓰는 프록시 — 무엇을 흉내 내고 무엇을 못 하나

보호자 사진은 못 구합니다. 그래서 판정(작업 규칙 7)은 **프록시**로 합니다 — 원본 라벨 사진을 "앱처럼" 가공한 것.
프록시가 답할 수 있는 건 **두 설정의 상대 비교**뿐이고, **절대값("앱에서 헛알림 34%")은 인용하면 안 됩니다.**

## 흉내 낸 것 (근거 있음)

| 실사용 요소 | 프록시 | 근거 |
|---|---|---|
| 가까이 찍음 | 라벨 bbox 긴 변 × U(3.5, 6.0) 창을 잘라 1080 정사각 | 사람 40장 실측: 병변이 화면의 5.6~59.6% (STEP 36) |
| 사용자 네모 | 긴 변 화면의 50~70% · 중심 이탈 중앙값 0.16 | 같은 40장 (`reports/box_error.json`) |
| 폰 업로드 화질 | STEP 48 만: 긴 변 1600 축소 + JPEG 90 | 앱 업로드 경로 |
| 정상/병변 비율 | 넘긴 사진 중 헛알림 몫 19% (STEP 31) 로 정상 장수 맞춤 | 실측 |

## 못 흉내 낸 것 — 알고 있어야 하는 구멍

- **자극이 정답에서 파생**: 창을 라벨 bbox 기준으로 자르니 병변은 항상 창 안. 실사용엔 "병변이 화면 밖" 도 있음
- **카메라·조명·흔들림**: 원본은 라벨링용 1920×1080. 폰 색감·초점·손떨림·역광은 없음. STEP 30 의 "입체감이 안 찍힘" 은 폰에서 더 심할 수 있음
- **사용자 네모 분포가 40장·한 사람**: 다른 보호자의 습관인지 모름
- **정상 사진 구도**: 정상도 라벨 네모 중심으로 잘랐는데 실제 보호자는 정상 피부를 겨냥해 찍지 않음 → 헛알림 프록시의 방향이 불확실 (STEP 48 의 51% 는 그래서 절대값 금지)
- **품종·부위·환경 분포**: AI Hub 구성 ≠ 앱 사용자 구성
- **한 사진에 병변 하나** 가정 (0.6% 만 여럿)

## 그래서

- 채택 관문은 프록시 안의 **차이**(`detect − user`, 같은 recall 에서 헛알림 차)로만
- 절대값이 필요한 자리(발표·앱 문구)엔 "라벨 네모 기준 X / 사용자 네모 프록시 기준 Y" 로 **둘 다** 적고 프록시임을 표시
- ★ **메우는 길은 하나 — 실제 앱 사진 100~200장.** 라벨 없이 병변 유무(보호자 답)만 있어도 헛알림·recall 의 **절대값 눈금**이 생깁니다. 개발 서버에 올라온 사진이 있으면 그게 첫 검증 데이터입니다
