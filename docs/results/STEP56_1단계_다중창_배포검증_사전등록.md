같은 표본(fold 0 2,500 + 586). 1단계 점수만 사용자 중심 3×3 평균으로 바꾸고 2단계는 지금대로.
커버리지는 확신도(`p1 × p(계열)`) 순위로 정해지므로 문턱과 무관합니다.

| **관문** | `s1mw_mean_user2 − user ≥ −2%p` (커버리지를 내주지 않을 것). 오르면 기록 |

## ② 문턱 재산정 (val, `tools/stage1_multiwindow_split.py --split val`)

평균 점수는 창 하나 점수보다 낮게 깔리므로 배포 문턱 0.1466 이 안 맞습니다. 배포 문턱과 같은 규칙 — **라벨 중심 조건에서 target recall 0.95** —
로 val 표본 5,000장(seed 7)에서 `label_mw_mean` / `label_mw_top3` 문턱을 뽑습니다. 같은 표본에서 창 하나 문턱도 다시 뽑아 배포값(0.1466)과
가까운지 봅니다(도구 검증).

## ③ holdout 1회 (`--split holdout --n 5000`, 문턱은 ②에서 가져옴)

⚠️ holdout 을 엽니다 — 이 도구가 다섯 번째입니다(05·06·07·12 + 이 도구). 결과를 보고 문턱·설계를 고치지 않습니다.

| | 값 | 근거 |
|---|---|---|
| **관문 A (상한 조건 유지)** | 라벨 중심 `label_mw_mean` AUROC ≥ `label_single` AUROC − 0.01, recall(각자 문턱) ≥ single − 0.01 | 라벨 네모 조건(holdout 0.9304)이 깨지면 안 됨 |
| **관문 B (보호자 조건 개선)** | 사용자 흉내 중심(±0.161): `user_mw_mean` recall ≥ `user_single` recall **+5%p**, 헛알림은 `user_single` **+2%p 이내** | STEP 55 의 헛알림 −5.5 가 holdout 에서도 "같은 헛알림에서 recall ↑" 로 나타나야 함 |
| 찍기만 | 위치 민감도(라벨 − 사용자 recall) single vs mw · top3 |

판정: 후보(①②③ 통과 → ④ 배선) / 구분 불가 / 기각.
