# STEP 19 — 클래스와 청크가 얽혀 있지만 모델은 안 씁니다 (2026-09-05)

GPU 0. 재현: `uv run --extra train python tools/chunk_shortcut.py`

## 왜 봤나

AI Hub 561 을 세 묶음으로 받아 합쳤는데 **묶음마다 담긴 클래스가 다릅니다.**
원리적으로 모델이 병변을 안 보고 "어느 묶음인가" 만으로 두 무리를 가를 수
있습니다 — 이 리포가 이미 두 번 잡은 지름길(크롭 배율 · 선명도)과 같은 종류입니다.

| 클래스 | TL01 | TL02 | VL01 |
|---|---:|---:|---:|
| A1 | **86.7%** | **0%** | 13.3 |
| A7 | **88.6%** | **0%** | 11.4 |
| A2 | 60.3 | 31.4 | 8.3 |
| A3 | **0%** | 88.9 | 11.1 |
| A4 | **0%** | 88.2 | 11.8 |
| A5 | **0%** | 92.5 | 7.5 |
| A6 | **0%** | 90.5 | 9.5 |

## ① 설계 상한선은 **낮습니다**

| | |
|---|---:|
| Cramer's V(라벨, 청크) | 0.601 |
| **청크만으로 병변 6종 macro-F1** | **0.2197** |
| 모델(2단계) macro-F1 대비 | **36.6%** (문턱 50%) |

표는 0%/88% 로 극단적인데 상한선은 왜 낮은가 — **VL01 에 7개 클래스가 다
있어서** 청크가 라벨을 결정하지 못합니다. 청크가 유일한 입력일 때 할 수 있는
최선은 묶음별 최빈 클래스로 찍기(TL01→A2, TL02→A3, VL01→A3)이고 그게 0.2197 입니다.

## ② 모델이 실제로 쓰나 — **정황 없음**

### (a) 한 청크(VL01) 안에서만 평가

거기선 청크가 상수라 단서로 못 씁니다.

| | macro-F1 |
|---|---:|
| VL01 안에서만 | **0.5805** |
| STEP 16 전체 val | 0.5999 |
| 차이 | **+0.0194** (문턱 0.02) |

**청크 단서를 없애도 성능이 그대로입니다.**
⚠️ 문턱에 아슬아슬하고, VL01 은 A5 70장·A6 126장뿐이라 macro-F1 이 흔들립니다.

### (b) 주된 청크가 같은 쌍 vs 다른 쌍

| | 쌍 수 | 평균 혼동률 |
|---|---:|---:|
| 주된 청크 **같음** | 14 | 0.0790 |
| 주된 청크 **다름** | 16 | 0.0822 |
| 비 | | **1.04** (문턱 0.70) |

청크를 쓰고 있다면 **다른 쌍이 훨씬 덜 헷갈려야** 합니다. 1.04 로 **차이가
없습니다.** 오히려 주된 청크가 다른 쌍이 상위 혼동을 차지합니다 —
A1→A3 0.213, **A4→A1 0.209**, A4→A2 0.206.

⚠️ 첫 판에서는 "청크 집합이 **분리된** 쌍" 으로 재려다 **0개**가 나왔습니다 —
VL01 에 전 클래스가 있어서 분리되는 쌍이 없습니다. **주된 청크** 기준으로
고쳐야 의미가 생깁니다 (`tools/chunk_shortcut.py` 주석에 남겨뒀습니다).

## 판정 — **문제 없음**

설계 상한선도 낮고(36.6%) 모델이 쓰는 정황도 없습니다((a) 잡음 안, (b) 비 1.04).

**A4→A1 이 최다 혼동인데 둘은 주된 청크가 다릅니다** (A4=TL02, A1=TL01).
청크 서명을 쓰고 있었다면 이 쌍이 제일 쉬워야 합니다. 그 반대라는 건
A1↔A4 혼동이 **진짜 시각적 유사성**이라는 쪽을 지지합니다 — 임상 해설의
"고름 유무로만 갈리고 각도·조명에 따라 안 보임" 과 방향이 맞습니다.

⚠️ **관찰입니다.** 못 박으려면 "사진으로 청크 맞히기" 를 학습시켜 AUROC 를
재야 합니다 (GPU 필요). 지금은 **축을 닫되 기록해 둡니다.**

## 덤 — 저장된 크롭의 실제 해상도

`save_crop_size=512` 는 **목표가 아니라 상한**이었습니다. 실측:

```
f320 : (321,320) (320,320) (320,321) …     ← 항상 320
m2.5 : (123,123) (64,64) (145,145) (278,278) …  ← 창 크기 그대로
```

즉 작은 병변의 `m2.5` 크롭은 **64px 짜리도 있고**, 384 입력에 넣으면 **6배 확대**
입니다. 2단계에서 "보간으로 뭉개진다" 는 여전히 살아 있는 가설입니다
(1단계는 STEP 18 에서 창 채움 쪽으로 결론).
