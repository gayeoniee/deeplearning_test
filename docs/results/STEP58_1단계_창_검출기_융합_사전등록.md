# STEP 58 — 1단계 점수 = 창 하나 점수 + 검출기(정상 학습) 점수의 평균 · 사전등록 (2026-09-13 저녁, 결과 전)

> 사용자 질문 *"중심이 안 맞았을 때만 검출기를 쓰는 식으로 경우에 따라 다르게 못 하나"* 에서 출발. STEP 52 표본(프록시 3,065장)의 저장된 점수로
> 합치기를 탐색하니 **`(창 + 검출기)/2`** 가 사용자 조건 AUROC 0.7525 → 0.7700, 헛알림 34.0 → 32.8% 이면서 **라벨 조건도 0.8473 → 0.8531 로 안 잃음**
> (다중 창이 진 자리에서 안 짐). 게이트(창 점수 낮을 때만 검출기)는 오히려 나빴음(0.735~0.748). 순위 평균은 사용자 −4.6%p 이나 라벨 −0.012 (참고).
> ⚠️ 프록시 통과는 후보 자격 — **원본 사진 val 5,000장(STEP 56 과 같은 표본)** 에서 확인한 뒤 holdout.

## 설계 (`tools/stage1_detector_fusion.py`)

- 검출기: STEP 52 D-FINE-M(정상 15만 장을 네모 0개로 같이 배움). 입력: 네모 중심 주변 **1080 정사각**(앱이 만들 수 있는 창), 최고 쿼리 점수.
- 창 하나 점수: STEP 56 val 2차 npz(같은 사진·같은 사용자 중심). 융합 `fuse_mean = (창 + 검출기)/2`. 문턱: val 라벨 중심 recall 0.95.
- 조건: 라벨 중심(상한) · 사용자 흉내 중심(±0.161).

## 관문 (STEP 57 과 같음)

| | 값 |
|---|---|
| **A 상한 유지** | 라벨 중심 `fuse_mean` AUROC ≥ 창 하나 − 0.01 · 같은 문턱 규칙에서 헛알림 ≤ 창 하나 + 2%p |
| **B 보호자 개선** | 사용자 흉내 `fuse_mean` recall ≥ 창 하나 + 5%p 이고 헛알림 ≤ + 2%p, **또는** AUROC ≥ +0.02 이고 헛알림 ≤ +2%p |
| 찍기만 | `fuse_rank` · 검출기 단독 |

val 에서 A·B 통과 → holdout 1회(같은 관문) → 통과 시 2단계 커버리지 → 배선(1단계에 검출기 추론 1회 추가, CPU 0.5s). 판정: 후보 / 구분 불가 / 기각.
val 에서 미달이면 holdout 안 엶.
