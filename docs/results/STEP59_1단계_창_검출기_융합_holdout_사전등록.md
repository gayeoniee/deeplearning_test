# STEP 59 — 창 + 검출기 평균(STEP 58)의 holdout 확인 · 사전등록 (2026-09-13 저녁, holdout 열기 전)

> STEP 58 은 val 에서 **구분 불가**(사용자 recall +3.9%p, 관문 +5). 사용자 지적: *"5% 는 누가 정했나, 4% 면 해볼 만하지 않나."*
> 맞는 지적입니다 — 그 5% 는 제가 교란 검사 잡음(±5%p, **하락률**의 잡음)에서 빌려온 값이고 recall 의 잡음이 아닙니다. 병변 2,536장에서 recall 의
> 2σ 는 약 ±1.4%p 라 +3.9 는 잡음 밖일 가능성이 큽니다. **STEP 58 의 판정은 안 고칩니다**(규칙 2). 대신 holdout 은 아직 안 열었으므로,
> 근거 있는 관문을 **새로** 적고 한 번 엽니다. val 이 탐색(가중치 훑기 포함)에 쓰였다는 사실은 여기 그대로 남깁니다 — 그래서 holdout 이 필요합니다.

## 점수 정의 (STEP 58 그대로, 가중치 0.5 고정 — val 훑기 결과로 고르지 않음)

`fuse = (창 하나 raw p + 검출기 최고 점수) / 2`. 검출기 = STEP 52 D-FINE-M(정상 학습), 입력 = 네모 중심 1080 정사각. 문턱 = STEP 58 val 라벨 중심 recall 0.95 값(0.0608).

## 관문 (holdout 5,000장 seed 7 · 같은 사진에서 창 하나와 나란히 · 짝지은 부트스트랩 1,000회)

| | 값 | 근거 |
|---|---|---|
| **A 상한 유지** | 라벨 중심 AUROC 차 ≥ −0.01 · 헛알림 차 ≤ +2%p | 정확한 네모에서 잃지 않을 것 |
| **B 보호자 개선** | 사용자 흉내 중심 recall 차 ≥ **+2%p 이고 95% CI 하한 > 0** · 헛알림 차 ≤ +2%p | +2 = "100마리 중 2마리" 가 제품에서 뜻이 있는 최소 크기, CI 로 잡음 배제 |
| 찍기만 | AUROC 차 · 검출기 단독 · 가중치 0.3/0.4 (참고, 판정 아님) |

판정: **후보**(A·B 통과 → 2단계 3팔 커버리지 확인 → 배선·릴리스 v2) / 구분 불가 / 기각. holdout 을 보고 문턱·가중치를 바꾸지 않습니다.
비용: 1단계에 검출기 추론 1회(CPU 0.5s). 검출기가 좋아지면(STEP 52 epoch 3 캐글 진행) 같은 관문으로 다시 한 번만 — 그때는 holdout 2회 노출로 적습니다.

## 실측

### holdout 5,000장 (2026-09-13 20:20, seed 7, 병변 2,549 · `reports/stage1_detector_fusion_holdout.{json,log,npz}`) — **holdout 노출 1회**

| 1단계 점수 (val 문턱 그대로) | 라벨 중심 AUROC | 라벨 recall / 헛알림 | 사용자 흉내 recall / 헛알림 | 사용자 AUROC |
|---|---:|---:|---:|---:|
| 창 하나 (지금 배포) | **0.9113** | 96.2% / 51.7% | 85.4% / 56.2% | 0.7322 |
| (창 + 검출기)/2 | 0.9085 | 96.7% / 56.8% | **89.8%** / 60.2% | 0.7432 |

- 사용자 recall 차 **+4.4%p, 95% CI [+3.4, +5.4]** — 잡음이 아닙니다(관문 B 의 recall 항목 통과).
- **관문 A 미달**: 라벨 헛알림 +5.0%p(허용 +2). **관문 B 미달**: 사용자 헛알림 +4.0%p(허용 +2). AUROC 는 라벨 −0.003(허용 안), 사용자 +0.011.

### 참고 (사후 계산, 판정 아님): 같은 recall 에서 헛알림

val 문턱을 holdout 에 옮기니 융합 쪽 recall 이 더 높게 걸려(96.7 vs 96.2) 헛알림 비교가 같은 자리가 아니었습니다. 같은 recall 로 맞추면:

| | 창 하나 헛알림 | 융합 헛알림 | 차 |
|---|---:|---:|---:|
| 라벨 중심, recall 96.2% | 51.6% | 52.5% | +1.0%p |
| 사용자 중심, recall 85.4% | 56.0% | 53.6% | **−2.4%p** |
| 사용자 중심, recall 90 / 93 / 95% | 65.5 / 71.8 / 79.1% | 60.5 / 66.7 / 73.5% | −5.0 / −5.1 / −5.6%p |

즉 융합의 **진짜 이득은 "같은 recall 에서 헛알림 −2.4~−5.6%p"** 입니다. 배포 문턱에서 본 recall +4.4 / 헛알림 +4.0 은 창 하나의 문턱을 낮추면
거의 비슷하게 얻는 맞바꿈이고(그 경우 헛알림 약 +6.4), 융합이 그보다 2.4%p 낫습니다.

### 판정: **구분 불가** (사전등록 문장 그대로 — 헛알림 항목이 관문을 못 넘음). 배선 안 켬, 릴리스 안 바꿈.

- 제 관문 설계의 흠: A·B 의 헛알림 항목을 **각자 문턱**에서 비교해 recall 이 다른 자리끼리 비교했습니다. 같은 recall 로 못 박았어야 했습니다.
  그래도 결과를 보고 관문을 고치지 않습니다(규칙 2). 같은 recall 값은 참고로만 적습니다.
- 제품 판단으로 보면: 이득은 실재하지만 작고(헛알림 −2.4%p 상당), 대가는 1단계에 검출기 추론(CPU 0.5s)·`transformers` 의존·릴리스에 검출기 가중치 추가.
  **지금 구성(v1)을 유지**하는 쪽을 권합니다. 검출기가 좋아지면(캐글 epoch 3, 참고용) 같은 표본에서 한 번 더 볼 수 있지만 그땐 holdout 2회 노출로 적습니다.
