# STEP 50 — 병변 검출기, 전체 원본으로 · **사전등록** (2026-09-11, 결과 전)

> 돌리기 전에 씁니다 (작업 규칙 2). 결과가 나오면 아래 "실측" 에 숫자만 붙이고
> 문턱·하한선·관문은 고치지 않습니다. STEP 42 의 기각을 **다시 묻는** 실험이라
> STEP 42 가 요구한 대로 **새로** 사전등록합니다.

## 질문

사람이 못 찾는 병변 위치를 **모델이 찾아서** 크롭을 걸면, 배포 조건에서 무너진
계열 4군 커버리지(라벨 네모 50.3% → 사용자 네모 22.4%, STEP 39)를 **얼마나 되찾나.**

## 왜 다시 묻나 — STEP 42 가 기각된 이유가 없어졌습니다

STEP 42 는 *둘 다 밴드 안 29.3%* (문턱 50%) 로 기각됐고, 그때 적어둔 한계가
**"VL01 하나로 배우고 VL01 로 쟀다 — 23,070장이 바닥, 더 줄 데이터가 없다"** 였습니다.
지금은 원본 191GB(TL01·TL02·VL01)가 로컬에 있습니다. 비 holdout 병변 **149,800장**(후보 157,493 중 자극 규칙 통과분;
STEP 42 21,880장의 **6.8배**) · 개체 2,007 · 세 청크. 막았던 원인이 실제로 없어진 유일한 축입니다.

그리고 판정 축을 바꿉니다: STEP 42 는 **밴드**(사람·창탐지기와 같은 잣대)로 기각했는데,
제품이 실제로 잃는 것은 **커버리지**입니다. 이번엔 커버리지가 주 관문이고 밴드는 참고로 찍습니다.

## 관문 — 돌리기 전에 못 박음

**주 관문(제품 지표): 검출기 네모로 자른 계열 4군 커버리지** — 같은 사진·같은 팔에서
`사용자 네모` 대비 **`+0.05` 이상** (`experiments.DETECT_MIN_COVERAGE_GAIN`, STEP 42 가 박아둔 값
그대로). 긴급도 하향 ≤ 5% 유지.

| 조건 (같은 사진) | 뜻 | 역할 |
|---|---|---|
| `label` | 라벨 네모 | **상한** (STEP 39: 50.3%) |
| `user` | 사용자 네모 시뮬레이션 (STEP 36 실측 분포) | **비교 기준** (22.4%) |
| `center` | 화면 한가운데 · 크기 0.215 고정 — 아무것도 안 배운 네모 | **하한선** |
| `fixed` | 사용자 중심 + 크기 0.215 | STEP 41 (−1.1%p 로 기각됐던 것) |
| **`detect`** | 검출기 네모 그대로 (중심 + 크기) | **판정 대상** |
| `detect_fixed` | 검출기 중심 + 크기 0.215 | 부지표 — 크기까지 배운 것이 값을 하나 |

부지표(찍기만): 밴드 `둘 다`(STEP 42: 29.3% · 하한선 6.1%) · 중심 오차 중앙값(0.132) ·
**1단계 recall** — 검출기 중심을 `f320` 에 줬을 때 (사용자 중심은 라벨 대비 −0.14, STEP 43).

⚠️ 커버리지 평가는 **로컬에 있는 릴리스 팔**(1단계 + 2단계 `convnextv2_base` 1팔)로 합니다.
STEP 39 의 22.4%/50.3% 는 3팔 값이라 **절대값을 그 표와 비교하면 안 됩니다** — 이 실험의
관문은 **같은 실행 안의 상대 차이**(`detect − user`)입니다. 표본: fold 0 병변 2,500 + 정상 586
(넘긴 사진 중 헛알림 몫 19% 를 맞춤, STEP 39 와 같은 규칙) · seed 31.

판정 문장은 셋 중 하나:
- **채택 후보** — `detect − user ≥ +0.05` → 다음: 3팔로 재측정 → holdout 한 번 → 서빙 배선
- **구분 불가** — 0 ~ +0.05
- **기각** — 이득 없음 → *"데이터 7배로도 위치를 못 찾는다"* 로 축을 닫음

## 하지 않는 것

holdout 안 엶 · 2단계 재학습 안 함 · 백본·해상도 스윕 안 함 · 결과 보고 문턱 안 고침.
관문 근처(±0.02)면 seed 하나 더 — 그 예산(코랩 유닛 ~40)을 남겨둡니다.

### 같이 읽어야 할 것

- **1단계 recall 이 거의 돌아옵니다** — 사용자 중심 72.9% → 검출기 중심 **84.8%** (라벨 86.8%). STEP 43 의 −0.14 중
  **−0.02 만 남습니다.** 2단계 커버리지보다 이쪽이 제품엔 더 큰 값일 수 있습니다 (놓친 병변은 "괜찮아 보여요" 로 나감)
- ⚠️ **1단계 헛알림이 34% → 52% 로 늘었습니다 (+18%p).** 검출기는 병변이 **없는** 사진에도 네모를 하나 내고, 그 자리는
  "제일 병변처럼 보이는 곳" 이라 1단계가 거기서 더 자주 이상이라고 합니다. 커버리지는 헛알림 포함 값이라 +17.1%p 는
  이 대가를 **치른 뒤** 숫자입니다 — 그래도 **관문에 안 넣은 반대쪽 지표**이므로 여기 찍습니다 (STEP 30 의 교훈).
  절대값(34%·52%)은 이 프록시(가까이 찍은 창·정상은 한가운데)가 부풀린 값이라 STEP 48 과 같이 **차이만** 읽습니다.
  → 배선할 때 결정할 것: 검출기를 **1단계 뒤에만**(이상 판정 뒤 2단계 크롭용) 쓸지, 1단계 중심에도 쓸지. 전자면
  헛알림 대가 없이 커버리지 이득만, 후자면 recall +12%p 와 헛알림 +18%p 를 맞바꿈
- 크기까지 배운 것이 값을 합니다 — `detect` 46.8% vs `detect_fixed` 42.3% (+4.5%p). STEP 42 의 *"배율은 하한선"* 이
  밴드에서는 맞지만 크롭 창에서는 크기 추정이 쓸모가 있습니다
- `fixed`(사용자 중심 + 고정 크기)가 여기서는 +8.8%p — STEP 41(VL01·3팔)의 −1.1%p 와 다릅니다. 팔 수·표본이 달라
  **판정을 뒤집지 않습니다**; 확대 측정 때 같이 봅니다

### 판정 문장

**채택 후보** — 사전등록 세 문장 중 첫째. 단일 seed 이지만 관문 여유(+12%p)가 사전등록의 재확인 구간(±0.02)을
한참 넘어 seed 반복은 요구되지 않습니다. 다음(사전등록대로): **3팔로 재측정 → holdout 한 번 → 서빙 배선.**
⚠️ 절대값(77.1 / 29.7 / 46.8%)을 STEP 39(50.3 / 22.4%)와 비교하지 마세요 — 팔 수·표본이 다릅니다.
