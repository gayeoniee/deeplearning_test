# STEP 54 — 2단계에 사용자 중심 창 여럿을 넣고 평균 (추론만, 재학습 0) · 사전등록 (2026-09-12, 결과 전)

> 돌리기 전에 씁니다. 로컬 CPU · 배포 3팔 · 같은 표본 · 작업 규칙 7(보호자 조건).

## 왜

배포 2단계는 사용자 네모가 포화돼 **사진 전체 하나**를 봅니다. STEP 25·26 에서 앙상블 이득의 정체가
*"비례 창 vs 고정 창 — 창의 다양성"* 이었습니다. 그렇다면 **같은 팔에 창을 여럿** 주는 것(사진 전체 + 사용자 중심
800 + 640)도 다양성입니다 — 사용자 중심은 아무것도 안 한 것보다 12%p 값이 있고(STEP 50 `center` 19.4 vs `user` 31.6),
좁은 창은 병변을 크게 보여주지만 중심 오차(0.16)로 병변을 놓칠 수 있어 **넓은 창과 평균**하면 그 위험을 나눕니다.
재학습 0 · 배포 변경은 추론 3배(3팔 × 3창).

## 설계

- 1단계: 사용자 조건 그대로 (`user`). 2단계: 창 {1080(전체), 800, 640} 을 사용자 중심에 놓고 각 창을 "사진" 으로 보아
  팔마다 자기 크롭(bbox 없음 → 중앙) → **3팔 × 3창 확률 평균** (`user1_multiwin`). 창 하나씩(`user1_mw*`)도 찍음.
- 표본·팔: STEP 50·51 과 같음 (fold 0 2,500 + 586 · seed 31 · HF v1 3팔).

## 관문

| | 값 |
|---|---|
| **주 관문** | `user1_multiwin − user ≥ +0.05` (커버리지, 보호자 조건) |
| 찍기만 | 창별 단독 · 계열 정확도 · 긴급도는 같은 도구에 없음(통과 시 `naming_coverage` 로 재확인) |

판정: 후보(→ 3배 추론 비용 vs 이득 논의, holdout) / 구분 불가 / 기각.

## 실측 (2026-09-12, 로컬 · `reports/detect_coverage_step54_multiwin_3arm.json`)

| 2단계 입력 | 커버리지 | 계열 정확도(병변) |
|---|---:|---:|
| `user` 사용자 네모 (지금 배포 = 포화된 사진 전체, f320 팔은 사용자 중심) | 31.6% | 77.7% |
| 창 1080 (사진 전체, 팔 크롭은 화면 중앙) | 22.1% | 74.6% |
| 창 800 (사용자 중심) | 30.5% | 76.5% |
| 창 640 (사용자 중심) | 31.9% | 76.1% |
| **창 셋 평균** (3팔 × 3창) | **34.1%** | **79.0%** |

**관문: +2.5%p < +5%p → 구분 불가.** 계열 정확도는 +1.3%p 로 방향은 맞습니다. 창 하나씩은 어느 것도 `user` 를
못 이기고, 셋을 평균해야 넘습니다 — STEP 25 의 *"창 다양성"* 이 같은 팔 안에서도 작게나마 보이는 모양.
⚠️ 창 1080 이 `user` 보다 낮은 이유: `user` 조건의 `f320` 팔은 사용자 중심을 쓰는데 창 1080 은 bbox 없음 → 화면 중앙 —
같은 사진이 아니라 `f320` 팔의 중심이 다릅니다. 사후 조합(참고만, 관문 아님): 창 800+640 평균 **34.0%** · `user`+800+640 평균 **35.3%** (+3.7%p) — 그래도 +5 미달.

판정 문장: **구분 불가.** 추론 3배 값을 치를 이득이 아닙니다. 채택 안 함. 남는 관찰은 *"2단계는 창을 여럿 주면 조금 낫다"*
정도이고, 그건 STEP 53(흔들어 배운 팔로 교체)이 학습 쪽에서 같은 것을 더 크게 노립니다.
