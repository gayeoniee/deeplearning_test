# STEP 52 — 검출기에 정상 사진을 "네모 없음" 으로 가르쳐 **1단계 후보**로 · 사전등록 (2026-09-12, 결과 전)

> 돌리기 전에 씁니다. 결과가 나오면 "실측" 에 숫자만 붙이고 문턱은 고치지 않습니다. **캐글 무료 T4** — 과금 0.

## 왜

- 1단계(`f320`)는 사용자 가이드 **중심**에 의존합니다. 실사용 조건(STEP 43·50 프록시)에서 recall 이 라벨 중심 86.8% → 사용자
  중심 **72.9%** — 놓친 병변은 "괜찮아 보여요" 로 나가는 가장 비싼 손실입니다.
- STEP 50 의 검출기 중심을 1단계에 주면 recall 은 **84.8%** 로 회복됐지만 헛알림이 34 → **52%**. 원인은 **검출기를 병변
  사진으로만 가르쳐** 정상 피부에서도 "제일 병변 같은 곳" 을 찍은 것 (정상에도 라벨 네모는 100% 있음 — 2026-09-12 정정).
- 사용자 관찰: *"정상을 같이 가르치면 헛알림이 줄 수도 있는 것 아닌가"* — 맞고, 시험된 적 없는 갈래입니다.
  정상 사진을 **정답 네모 0개**로 넣으면 검출기의 **최고 점수 자체가 "병변이 있나" 의 점수**가 되고, 사진 전체를 훑으므로
  **사용자 중심에 의존하지 않습니다.**

## 설계

| | |
|---|---|
| 데이터 | 병변 창 149,800장(`dogskin-detect-full-{0,1,2}` + `boxes_multi`) + **정상 창 전부** ~150k(`dogskin-detect-normals-{0,1,2}`, 같은 창 규칙, 정답 네모 없음). holdout 제외. **fold 0 = 검증** (병변 31k + 정상 31k) |
| 모델 | **D-FINE-M** (`ustc-community/dfine-medium-obj2coco`, 19M, Apache-2.0) · 입력 **512** · 1클래스. ⚠️ STEP 51(L·640)과 다름 — T4 한 세션(12h)에 2 epoch 을 넣기 위해. 별개 질문이라 비교 대상이 아님 |
| 학습 | 증강 `dfine`(STEP 51 과 같음: hflip·줌 0.5~2.0·밝기/대비/채도·다중 스케일 416~608·마지막 epoch 끔) · AdamW 1e-4(백본 0.05×) · **EMA 워밍업** · fp16+GradScaler(T4) · BS 16 · **3 epoch**, 1세션에 2 epoch → 판정, 오르고 있으면 2세션에 3 epoch |
| 실행 | 캐글 노트북 `21` · Save & Run All · 출력 ZIP → Dataset 으로 재개 (STEP 49 에서 검증된 경로) · 예상 epoch 4h |

## 관문 — 돌리기 전에 못 박음

판정 표본은 STEP 50·51 과 **같은 사진**(fold 0 병변 2,500 + 정상 586, seed 31, 가혹 조건) — `tools/detect_coverage.py` 에
`--detector-stage1` 조건 추가. 검출기 **최고 쿼리 점수**를 1단계 점수로 씁니다 (사용자 중심 안 씀).

| | 값 | 근거 |
|---|---|---|
| **주 관문** | 현 1단계(사용자 중심 `f320`)의 recall **72.9%** 에 맞춘 문턱에서 **헛알림이 34.3% 보다 5%p 이상 낮을 것** | STEP 50 에서 검출기 중심 1단계는 recall +12 / 헛알림 +18 이었음. 정상 학습이 그 +18 을 되돌리고도 남아야 값이 있음 |
| 부관문 | AUROC ≥ 현 1단계(같은 프록시에서 잰 값) | 문턱 하나로 못 보는 변별력 |
| 찍기만 | recall 상한(같은 헛알림 34.3% 에서) · 병변 검출 밴드·중심 오차(STEP 51 과 나란히) · 2단계 커버리지(검출기 네모, 배포 3팔) |
| 하한선 | 화면 한가운데 320 창의 `f320`(`center` 조건: recall 63.3%, 헛알림 33.1%) | 아무 위치 정보도 없을 때 |

판정 문장: **후보**(주·부 통과 → holdout 재확인 후 1단계 교체/병행 논의) / **구분 불가** / **기각**. ⚠️ 프록시의 절대값(34%·52%)은
가혹 조건 값 — 결론은 같은 실행 안의 차이. ⚠️ 통과해도 **holdout(1단계 AUROC 0.9304)** 을 넘어야 배포입니다 — 그건 별도 단계.

## 하지 않는 것

2단계 재학습 안 함 · holdout 안 엶 · 결과 보고 문턱 안 고침 · 코랩 과금 안 함 (41 유닛은 예비).
