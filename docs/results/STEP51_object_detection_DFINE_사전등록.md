# STEP 51 — 진짜 object detection (D-FINE) 으로 병변 위치 찾기 · **사전등록** (2026-09-11 밤, 결과 전)

> 돌리기 전에 씁니다. 결과가 나오면 "실측" 에 숫자만 붙이고 문턱·하한선·관문은 고치지 않습니다.
> 멘토 피드백(2026-09-11): *"bbox 라벨이 있고 크기가 다양하니 object detection 으로 1차 검출·검증, 2차 분류.
> 증강은 분석으로 고르는 것과 마구 실험하는 것을 같이."*

## 왜 — STEP 50 이 남긴 것

STEP 42·50 의 "검출기" 는 object detection 이 **아니었습니다** — 분류기 백본 끝의 좌표 4개 회귀. 데이터를 6.8배 줘도
중심 오차 중앙값이 **0.107** 에서 평평해졌고, 그 오차(1080px 에서 111px)는 `m2.5` 창 여유(~147px)에 자주 걸려 배포
3팔에서 사진 전체보다 못했습니다(−0.9%p). 라벨 네모(오차 0)면 커버리지가 **58.8%** 라 상금은 그대로 있습니다 —
**위치를 절반 이상 더 정확히** 찾아야 합니다. 그건 회귀 헤드의 한계이지 데이터의 한계가 아닙니다.

| YOLO 계열 | 제외 | AGPL |

**1클래스("병변")** 로 시작합니다. 6클래스(검출+분류 한 모델)는 1클래스가 커버리지를 올린 **뒤** 별도 사전등록 —
위치를 못 찾는데 이름을 붙일 수는 없습니다. 병변별 6개 모델은 같은 사진을 6번 돌리고 네모 충돌 규칙이 또 필요해
6클래스 하나가 표준입니다 (멘토 의도인 "검출 1차 → 분류 2차" 는 그대로).

## 관문 — 돌리기 전에 못 박음 (STEP 50 과 같은 잣대, **처음부터 배포 3팔**)

| | 값 | 근거 |
|---|---|---|
| **주 관문** | 배선 `1단계 사용자 중심 그대로 · 2단계만 검출기 크롭` 의 계열 4군 커버리지, **배포 3팔**, 같은 표본(fold 0 병변 2,500 + 정상 586, seed 31): `− user ≥ +0.05` | `DETECT_MIN_COVERAGE_GAIN`. STEP 50 에서 이 배선은 **−0.9%p** |
| 상한 / 기준 / 하한선 | 라벨 58.8% / 사용자 31.6% / 한가운데 19.4% (STEP 50 ④, 같은 표본) | 같은 실행에서 다시 찍음 |
| 부관문 (위치) | fold 0 전체에서 **중심 오차 중앙값 ≤ 0.05** (STEP 50: 0.107, 사람 0.161) | `m2.5` 창 여유(147px ≈ 0.136)의 절반 아래 — STEP 41·50 산수 |
| 찍기만 | 밴드 둘 다(STEP 50: 39.2%) · 크기비 · `두 단계 다` 배선(헛알림 같이) · `detect_fixed` · 1단계 recall/헛알림 |

**판정 문장**: 채택 후보(주 관문 통과) / 구분 불가(0 ~ +0.05) / 기각(이득 없음). ⚠️ **1팔로는 판정하지 않습니다** — STEP 50 에서
1팔은 상대 차이의 부호까지 틀렸습니다. 부관문(오차 0.05)을 통과하고도 주 관문이 미달이면 *"위치는 충분한데 꽉 맞는
창이 다른 이유로 사진 전체를 못 이긴다"* 로 적고, 다음 질문은 STEP 49 의 `safe` 2단계입니다.

## 실측 ① — 학습 (2026-09-12, 코랩 A100, 6/8 epoch 에서 중단)

`SWEEP=False`(증강 비교 생략 — epoch 당 61~80분이라 시간상), 조합 `dfine`. epoch 1 뒤 런타임이 끊겨 재개했고, 그때
**EMA 워밍업 누락**을 발견해 고쳤습니다 (워밍업 없는 0.9999 EMA 는 첫 epoch 뒤에도 절반이 초기 헤드 → epoch 1 평가
크기비 3.7배). epoch 2 부터는 정상 EMA. fold 0 표본 6,000장, top-1 네모 vs 가장 큰 정답.

## 실측 ② — 주 관문 (배포 3팔, 2026-09-12, 로컬 · `reports/detect_coverage_step51_dfine_3arm.json`)

같은 표본(fold 0 병변 2,500 + 정상 586, seed 31) · HF 릴리스 v1 3팔 · best = epoch 2 EMA.

| 배선 | 커버리지 | `− user` | 계열 정확도(병변) | 1단계 recall | 헛알림 |
|---|---:|---:|---:|---:|---:|
| `label` 상한 | 58.8% | +27.1%p | 82.0% | 86.8% | 34.0% |
| `user` 기준 | **31.6%** | — | 77.7% | 72.9% | 34.3% |

밴드(병변 2,479장): 둘 다 33.7% · 위치 45.1% · **중심 오차 중앙값 0.124** (STEP 50 회귀 헤드 0.103 — 같은 표본).

**판정: 기각.** 주 관문 미달(−5.4%p), 부관문 미달(0.124 ≫ 0.05). 진짜 object detection 이 STEP 50 의 회귀 헤드보다 **위치가
더 나쁘고**, 커버리지도 더 낮습니다(26.3 vs 30.7%). 1단계 중심으로 쓰면 recall 은 88.7% 까지 오르지만 헛알림 61.4%.

### 이 결과가 말하는 것

- **세 종류의 위치 모델이 전부 0.10~0.12 에서 멈췄습니다** — 회귀 헤드(VL01, STEP 42) 0.132 → 회귀 헤드(7배, STEP 50) 0.107 →
  D-FINE(STEP 51) 0.118~0.124. 모델 종류·데이터 양을 바꿔도 같은 자리. **벽은 모델이 아니라 라벨 쪽**입니다: 번진 병변
  (비듬·각질·태선화)엔 정의된 "중심" 이 없고(STEP 37 에서 사람도 병변 안 47.5%), bbox 는 그 외곽선의 외접사각형이라
  그 정확한 중심·크기를 사진만 보고 다시 맞히는 건 사람도 모델도 못 합니다.
- D-FINE 은 epoch 2 이후 검증이 계속 나빠졌습니다(과적합) — 데이터 15만 장이 "적어서" 가 아니라 **맞힐 수 없는 정답**을
  외우기 시작한 모양입니다.
- 따라서 *"위치를 더 정확히 찾아서 꽉 맞는 창을 건다"* 는 갈래는 **닫습니다** (STEP 42·50·51). 남는 길은
  ① 창이 어긋나도 견디는 2단계(STEP 49 `safe`) ② 검출기를 위치가 아니라 **"병변이 있나"** 에 쓰기 — STEP 52 (정상을 같이
  가르쳐 1단계 후보로, 사용자 중심 의존 제거).
