## 왜 — STEP 50 이 남긴 것

STEP 42·50 의 "검출기" 는 object detection 이 **아니었습니다** — 분류기 백본 끝의 좌표 4개 회귀. 데이터를 6.8배 줘도
중심 오차 중앙값이 **0.107** 에서 평평해졌고, 그 오차(1080px 에서 111px)는 `m2.5` 창 여유(~147px)에 자주 걸려 배포
3팔에서 사진 전체보다 못했습니다(−0.9%p). 라벨 네모(오차 0)면 커버리지가 **58.8%** 라 상금은 그대로 있습니다 —
**위치를 절반 이상 더 정확히** 찾아야 합니다. 그건 회귀 헤드의 한계이지 데이터의 한계가 아닙니다.

**1클래스("병변")** 로 시작합니다. 6클래스(검출+분류 한 모델)는 1클래스가 커버리지를 올린 **뒤** 별도 사전등록 —
위치를 못 찾는데 이름을 붙일 수는 없습니다. 병변별 6개 모델은 같은 사진을 6번 돌리고 네모 충돌 규칙이 또 필요해
6클래스 하나가 표준입니다 (멘토 의도인 "검출 1차 → 분류 2차" 는 그대로).

## 관문 — 돌리기 전에 못 박음 (STEP 50 과 같은 잣대, **처음부터 배포 3팔**)

| | 값 | 근거 |
|---|---|---|
| **주 관문** | 배선 `1단계 사용자 중심 그대로 · 2단계만 검출기 크롭` 의 계열 4군 커버리지, **배포 3팔**, 같은 표본(fold 0 병변 2,500 + 정상 586, seed 31): `− user ≥ +0.05` | `DETECT_MIN_COVERAGE_GAIN`. STEP 50 에서 이 배선은 **−0.9%p** |
| 상한 / 기준 / 하한선 | 라벨 58.8% / 사용자 31.6% / 한가운데 19.4% (STEP 50 ④, 같은 표본) | 같은 실행에서 다시 찍음 |
| 부관문 (위치) | fold 0 전체에서 **중심 오차 중앙값 ≤ 0.05** (STEP 50: 0.107, 사람 0.161) | `m2.5` 창 여유(147px ≈ 0.136)의 절반 아래 — STEP 41·50 산수 |
| 찍기만 | 밴드 둘 다(STEP 50: 39.2%) · 크기비 · `두 단계 다` 배선(헛알림 같이) · `detect_fixed` · 1단계 recall/헛알림 |

**판정 문장**: 채택 후보(주 관문 통과) / 구분 불가(0 ~ +0.05) / 기각(이득 없음). ⚠️ **1팔로는 판정하지 않습니다** — STEP 50 에서
1팔은 상대 차이의 부호까지 틀렸습니다. 부관문(오차 0.05)을 통과하고도 주 관문이 미달이면 *"위치는 충분한데 꽉 맞는
창이 다른 이유로 사진 전체를 못 이긴다"* 로 적고, 다음 질문은 STEP 49 의 `safe` 2단계입니다.
