> 2026-09-08 · 캐글 T4 · 노트북 `13_병변_검출기.ipynb` · **val 로만 판정** (holdout 안 엶)

## 한 줄

**기각**입니다 — 제안 네모가 배율·위치 밴드에 **둘 다** 드는 비율이 **29.3%** 로
사전등록 문턱 **50%** 에 못 미칩니다. 문턱은 옮기지 않았습니다.

★ 다만 **아홉 갈래 중 제일 멀리 갔습니다** — 사람 5.0% · 창 탐지기 6.7% 의

## 무엇을 했나

네모를 받는 길 아홉 개가 전부 같은 곳에서 막혔습니다 — **사람은 병변이 어디에
얼마나 크게 있는지 못 알려줍니다** (STEP 36~41). 그런데 `bbox` 라벨이 있는데도
**모델에게 네모 찾는 일을 직접 가르친 적이 없었습니다.**

⚠️ STEP 37 의 *"모델이 제안"*(6.7%) 과 다릅니다 — 그건 **분류기를 창 탐지기로
빌려 쓴 것**이라 네모를 뽑도록 배운 적이 없는 모델이었습니다.

| | |
|---|---|
| 데이터 | **21,880장** · 개체 1,491 (앱처럼 가까이 찍은 사진 + 정답 네모) |
| 분할 | 개체 단위 — 학습 18,412 / 평가 3,468 · 개체 1,267 / 224 (**겹침 0**) |
| 모델 | `effnetv2_s` + 네모 회귀 헤드 (중심 sigmoid · 크기 **로그**) |
| 학습 | 384px · 6에폭 · BS 24 · AdamW lr 2e-4 · cosine · **34.6분** |

⚠️ **크롭 데이터셋을 안 썼습니다** — `m2.5`·`f320` 은 병변을 가운데 놓고 자른
것이라 정답이 항상 한가운데입니다. 모델이 "가운데" 만 외우면 만점이 나옵니다.
그래서 원본에서 따로 만들었고, 자극 검사(중심의 화면중앙 이탈 중앙값 **0.242** ·
정중앙 비율 0.6%)를 올리기 전에 통과시켰습니다.

## ★ 하한선 — 사전등록 때 안 적어둔 값

`배율 75.0%` 를 보고 *"배율은 풀렸다"* 고 읽을 뻔했습니다. 같은 val 에서
**아무것도 안 배운 네모**(화면 한가운데 · 크기는 실측 병변 중앙값 0.215 고정)가
**배율 72.3%** 입니다.

    축      하한선    검출기    순이득
    배율    72.3%    75.0%    +2.7%p     <- 거의 전부 하한선입니다
    위치    10.1%    38.7%   +28.6%p     <- 검출기가 실제로 배운 것
    둘 다    6.1%    29.3%   +23.2%p

★ **검출기가 배운 것은 위치입니다.** 중심 오차를 0.248 → 0.132 로 **절반**
줄였습니다. 배율에서 번 것은 +2.7%p 뿐입니다 — 병변 크기가 원래 좁게 모여 있어
(긴 변 p25 0.183 ~ p75 0.274) **중앙값만 찍어도 밴드에 듭니다.**

⚠️ **하한선 6.1% 가 사람 5.0% · 창 탐지기 6.7% 와 같은 구간입니다.** 즉 STEP 36·37
에서 잰 둘은 **아무것도 안 한 것과 구분이 안 됐습니다.** 그때는 그 사실을
몰랐습니다 — 하한선을 안 쟀으니까요.

⚠️ 이건 STEP 29 와 **같은 실수**입니다 (계열 정확도 0.84 를 앞세웠는데 최빈
묶음만 말해도 0.671). 작업 규칙 1 을 사전등록에서 또 빠뜨렸습니다.
→ 이제 `detect.band_report()` 가 하한선을 **같이 냅니다**
(`tests/test_detect.py::[8]`).

## 두 축은 서로 독립입니다

    배율 75.0% x 위치 38.7% = 29.0%      (관측 29.3%)

거의 정확히 곱입니다 — **배율이 맞는 사진과 위치가 맞는 사진이 따로 놉니다.**
그래서 `둘 다 50%` 를 넘으려면 배율을 그대로 두고도 **위치가 67%** 여야 합니다.
지금 중심 오차 중앙값이 0.132 이고 밴드가 0.10 이니 **오차를 다시 절반**으로
줄여야 하는 셈입니다. 검출기는 이미 하한선 대비 절반을 줄였습니다.

## 안 한 것 / 못 한 것 — 정직하게

### ★★ 검출기는 **VL01 하나로** 배우고 VL01 로 평가했습니다

로컬에 남은 원본이 `VL01.zip` 하나뿐입니다 (다른 청크는 크롭만 남기고
지웠습니다 — 다른 PC 도 같습니다). 그래서:

    로컬 매니페스트            45,885행  (chunk_VL01 하나)
    검출 후보 풀 (A7 제외)      23,070행
    실제 담긴 것                21,880장  = 풀의 94.8%

★ **`--n 23000` 은 제가 건 문턴이 아니라 바닥이었습니다.** 원본 없이
더 쓸 수 있는 것은 **1,190장 (1.05배)** 뿐입니다.

⚠️ **평가도 VL01 입니다.** VL01 은 지표마다 방향이 다른 청크이고
(macro-F1·A4 recall 에서 낙관적 / 커버리지·A6 경보에서 비관적),
**병변이 다른 청크보다 큽니다** (A4 기준 196px vs TL02 113px). 검출은
병변 크기가 직접 걸리는 과제라 **밖에서 어떤지 모릅니다.**

### 원본을 다시 받을 수 있나 — 지금은 안 됩니다

    디스크 여유      10.0GB / 237.8GB
    TL01           90GB   + 받는 동안 2~3배 필요
    TL02          250GB   > 디스크 전체 — **물리적으로 불가**

### 그 밖에 안 본 것

* 백본·해상도를 한 조합만 봤습니다 (`effnetv2_s` · 384px)
* **한 장에 네모 하나**만 냅니다. 22% 는 병변이 여럿인데 가장 큰 것을 답으로 썼습니다
* 단일 회귀 헤드만 봤습니다 — 중심 추정에 더 유리한 히트맵 방식은 안 봤습니다
* **holdout 을 안 열었습니다**

⚠️ 그래도 **이번 판정은 기각입니다.** 위 항목들은 *"다음에 이렇게 하면
달라질 수도"* 이지 이번 결과를 뒤집는 근거가 아닙니다. 다시 물으려면
**새로 사전등록**해야 합니다.

   축을 다시 열 사람은 **위치만** 보면 됩니다.
3. **loss 와 판정 지표는 다른 것을 잽니다.** loss −67% 에 밴드 +2.7%p 였습니다.
   학습 곡선이 예뻐도 관문은 안 움직일 수 있습니다.
