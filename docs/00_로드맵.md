# 로드맵 — 지금 어디쯤인가

반려견 피부질환 스크리닝 보조 모델 프로젝트의 전체 진행표입니다.

---

## 전체 흐름

**AI Hub 는 해외 IP 다운로드를 차단**하므로 역할을 나눕니다.

```
━━━ 한국 PC (CPU 만) ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  STEP 1  다운로드        prepare_local.py --chunk VL01
  STEP 2  스캔            (--chunk 중 자동 출력)  ← ★ 결과 공유 지점
  STEP 3  전처리          prepare_local.py --finalize
          패키징          prepare_local.py --package
                             │
                             │  dogskin_prepared.zip (2~5GB)
                             ▼  Google Drive 업로드
━━━ Colab (GPU) ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  STEP 4A 2단계 베이스라인 notebooks/03  ← 크롭 확인 + 파이프라인 검증 게이트
  STEP 4B 모델 비교        notebooks/04
  STEP 5  평가·보정        notebooks/05  ← Grad-CAM 게이트
          배포 검토        docs/basics/10
```

> **노트북 번호가 03부터 시작합니다.** 데이터 확보·확인·전처리(옛 00~02)는
> 노트북이 아니라 `prepare_local.py` 가 전담합니다 — AI Hub 가 해외 IP 를 막아서
> 그 단계는 한국 PC 에서만 돌아가기 때문입니다. 번호는 위 STEP 과 맞춰 두었습니다.

### 🔄 STEP 4A — 2단계 베이스라인 (1회차 완료, 2회차 진행)

**노트북 03 을 위에서 아래로 순서대로 돌리면 됩니다.** 7번까지가 필수입니다.

| | 하는 일 | 학습 | 시간 |
|---|---|---|---|
| 1 | 크롭 감사 — 배율 지름길·`full` 천장·하한선 | — | 2분 |
| 2 | 2단계 뷰 (1단계 크롭 자동 결정) | — | 1분 |
| 3 | 1단계 학습 + 게이트 | ✅ | ~40분 |
| 4 | 2단계 학습 + 게이트 | ✅ | ~40분 |
| 5 | 두 단계 이어붙인 실제 성능 | — | 3분 |
| 6 | 실사용 견고성 (배율·위치 교란) | — | 5분 |
| 7 | **결과 저장 — 여기까지가 필수** | — | 1분 |
| 8 | (선택) 파인튜닝 강도 / 크롭 비교 / 증강 — 전부 주석 처리 | | |

**게이트**:
- 1단계 AUROC > 0.80
- 2단계 `macro-F1 > 0.25` (랜덤은 0.167) + 하한선 대비 +0.15 이상
- 배율·위치 교란 하락 < 15%

못 넘으면 모델이 아니라 **데이터를 다시 보세요.**

1회차 실측(0.8031 / 0.4865)은 [`results/STEP4A_베이스라인_실측.md`](results/STEP4A_베이스라인_실측.md).
2회차는 파인튜닝 강도를 `moderate`(백본 lr ×0.3)로 올리고 에폭을 늘렸습니다 —
1회차에서 12에폭 전부 best 갱신이었고 train/val 격차도 작아 **덜 배운 상태**였기 때문입니다.

### ⬜ STEP 5 — 평가 · 보정 · 안전장치

온도 스케일링 → 거절 임계값 → **Grad-CAM 게이트** → holdout 최종 평가 (파이프라인 기준)

**게이트**:
- CAM–병변 정렬도 `median_lift ≥ 1.3` — 못 넘으면 정확도와 무관하게 **재작업**
- **배율·위치 교란 하락 < 15%** (`robust.report`) — 넘으면 배포 불가
- holdout 스크리닝 recall ≥ 0.95

⚠️ 임계값은 **검증셋에서 정하고** holdout 에서는 확인만 합니다.
holdout 을 보고 임계값을 고치면 더 이상 holdout 이 아닙니다.

**노트북**: `05_평가_보정_GradCAM.ipynb`

## 목표 성능 (실측 기준으로 수정됨)

**파이프라인 기준**으로 봅니다. 2단계만 좋아도 사용자에게 도달하지 않습니다.

> ⚠️ 이전 목표 "6종 macro-F1 0.70~0.80" 은 **데이터를 보기 전 추정치**였고
> 근거가 없었습니다. VL01 실측 기준선(ResNet50/224px/12에폭)이 0.4865 라
> 측정 가능한 값으로 다시 잡았습니다. 낮추는 게 아니라 **현실화**입니다 —
> 못 넘을 숫자를 걸어두면 판단이 흐려집니다.
> → [`results/STEP4A_베이스라인_실측.md`](results/STEP4A_베이스라인_실측.md)

| 지표 | 실측 기준선 | 목표 (VL01 단독) |
|---|---|---|
| **스크리닝 recall** (병변을 놓치지 않은 비율) | — | **≥ 0.95** ← 가장 중요 |
| 헛알림 비율 (정상 → 이상) | 0.36 | < 0.5 ✅ |
| 1단계 AUROC (`full` 크롭) | 0.8031 | ≥ 0.85 |
| 2단계 6종 macro-F1 | **0.4865** | **0.55 ~ 0.65** |
| **A6 recall** (종양 감별) | **0.328** | **≥ 0.50** ← 최우선 |
| 모든 병변 클래스 recall | 0.33~0.61 | ≥ 0.40 |
| 보정 후 ECE | — | < 0.10 |
| CAM–병변 정렬도 `median_lift` | — | ≥ 1.3 |
| 배율·위치 교란 시 점수 하락 | — | < 15% |

> 0.70+ 는 TL01 을 붙이고 백본을 바꾼 뒤에 다시 볼 숫자입니다.

> ⚠️ 개체 단위 분할에서 **0.95+ 가 나오면 누수를 의심**하세요.
> 축하할 숫자가 아니라 검증해야 할 숫자입니다.
