## 5. 세 번째 벽 — 제가 추측한 스키마가 틀렸습니다 (3곳)

JSON 라벨 파일을 열어보기 전에 "이렇게 생겼겠지" 하고 파서를 썼는데,
`diagnose.py` 로 실물을 열어보니 **세 군데가 틀렸습니다**:

1. **라벨 필드** 위치가 다름
2. **좌표 형식** 이 다름 (polygon/bbox 구조)
3. **개체 ID** 를 엉뚱한 곳에서 읽고 있었음

3번이 특히 치명적입니다. 개체 ID 는 **데이터 누수(data leakage)** 를 막는 열쇠거든요.

> 📘 **데이터 누수란**: 같은 강아지 사진이 학습셋과 검증셋에 나눠 들어가는 것.
> 개체당 평균 50장이라, 무작위로 나누면 거의 확실히 섞입니다.
> 그러면 모델은 "이 병변" 이 아니라 **"이 강아지"** 를 외워서 맞히고,
> 검증 점수만 예쁘게 나옵니다. 실사용에서는 처음 보는 강아지뿐이라 그대로 무너집니다.

→ `split.py` 는 `StratifiedGroupKFold(groups=animal_id)` 로 **개체 단위 분할
(group-aware split)** 을 하고, `verify()` 가 누수를 발견하면 **에러를 던집니다.**
경고가 아니라 에러인 이유는, 경고는 무시되기 때문입니다.

**교훈**: 스키마는 추측하지 말고 열어봅니다. 그래서 `scan.py` 는 구조를 가정하지 않고
**추론**하도록 썼습니다.

## 6. 문제 정의를 2단계로 나눴습니다

처음엔 "병변 6종 분류" 한 판으로 생각했는데, 데이터에 **무증상(정상)** 이 있는 걸
확인하고 구조를 바꿨습니다.

```
사진 ──▶ ① 정상 / 이상  ──이상이면──▶  ② 병변 6종 (A1~A6)
         (스크리닝)                    (어떤 종류인지)
```

**왜 나누나**: 우리 목적이 "병원 가보세요" 라서, 1단계에서 **놓치는 것(false negative)**
이 제일 나쁩니다. 그래서 1단계는 **재현율(recall) 0.95 를 먼저 고정**하고
임계값을 잡습니다. 반면 2단계는 이미 "이상" 인 사진들 중 종류를 고르는 거라
기준이 다릅니다. 한 판으로 묶으면 이 둘을 따로 조절할 수 없습니다.

병변 6종:

| 코드 | 이름 | 영문 |
|---|---|---|
| A1 | 구진·플라크 | papule / plaque |
| A2 | 비듬·각질 | scale / crust |
| A3 | 태선화·과다색소침착 | lichenification / hyperpigmentation |
| A4 | 농포·여드름 | pustule / acne |
| A5 | 미란·궤양 | erosion / ulcer |
| A6 | 결절·종괴 | nodule / mass |

## 7. "지름길(shortcut)" 이라는 개념을 코드로 만들었습니다

선행 프로젝트들이 알려준 함정: **병변이 이미지의 5% 미만인 경우가 93%.**
전체 사진으로 학습하면 모델이 병변이 아니라 **배경(바닥·목줄·조명)** 을 봅니다.

그래서 병변 주변만 잘라내는 **ROI 크롭**을 씁니다. 그런데 여기서 새 위험이 생깁니다.

> 💡 **비유**: 시험 문제를 푸는데, 정답인 문제만 종이가 살짝 크다면?
> 학생은 문제를 안 읽고 **종이 크기만 보고** 정답을 고릅니다.
> 그리고 실제 시험(배포)에서는 종이가 다 똑같아서 완전히 틀립니다.

크롭 창 크기가 병변 크기에 비례하니까, **창 크기 자체가 정답을 흘릴 수** 있습니다.
그래서 만든 것:

* **하한선(shortcut baseline)** — 사진을 **아예 안 보고** 메타데이터(크롭 크기 등)만으로
  맞혀봅니다. 이 점수가 높으면 지름길이 있는 겁니다.
* **고정 픽셀 크롭 `f320`** — 창 크기를 320px 로 고정해 신호를 없애는 대안.
* **클래스별 비교** — 지름길은 **평균에 안 보입니다.** 전체 평균은 멀쩡한데
  특정 클래스만 크게 떨어지는 식이라, 클래스별로 봐야 잡힙니다.

오늘은 도구만 만들었고, 실제 판정은 Day 2~4 에서 나옵니다.
