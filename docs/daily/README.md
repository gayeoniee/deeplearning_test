## 쓰는 규칙

1. **숫자는 실측만.** 추정치는 "추정" 이라고 적습니다 (`CLAUDE.md` 작업 규칙 1번).
2. **틀린 것도 적습니다.** 되돌린 결정이나 잘못 이해한 것은 지우지 않고 정정으로
   남깁니다. 나중에 같은 실수를 반복하지 않으려면 "왜 그렇게 생각했는지" 가 남아 있어야
   합니다.
3. **실패한 실험이 성공한 실험만큼 값어치가 있습니다.** 증강 3회 실패가 크롭 실험의
   근거가 됐습니다.

## 누적 스킬 (skills) — 5일치 합계

날짜별 로그마다 「오늘의 스킬」 표가 있습니다. 아래는 프로젝트 전체에서 쓴 것을
합쳐 분류한 것입니다.

### 도구와 라이브러리

| 분류 | 쓴 것 |
|---|---|
| 언어·패키지 | Python 3.10+, **uv**(lock 1개), Windows/cp949 대응 |
| 딥러닝 | **PyTorch 2.x**, **timm**(resnet50 / effnetv2_s), AMP, EMA, cosine + warmup |
| 데이터 | **pandas** + **pyarrow**(parquet), **albumentations**, **Pillow**, **imagehash**(phash) |
| 분할·평가 | **scikit-learn**(`StratifiedGroupKFold`), 부트스트랩 CI, AUROC / macro-F1 / ECE |
| 설명·보정 | **Grad-CAM**(pytorch-grad-cam), 온도 스케일링(temperature scaling) |
| 데이터 확보 | **aihubshell** CLI 래핑, tar/zip 스트리밍 처리 |
| 클라우드 | **Kaggle** / **Colab** 환경 감지, Secrets, Save & Run All 인계 |
| 품질 | 자체 테스트 러너 200+ 검사, **AST 기반 노트북 정적 분석** |

### 개념과 기법

| 주제 | 배운 것 |
|---|---|
| **데이터 무결성** | 데이터 누수(data leakage), 개체 단위 분할(group-aware split), 부분 업로드 감지 |
| **지름길 학습** | 하한선(shortcut baseline), 크롭 창 크기 지름길, **화질 지름길**, 클래스별로 봐야 보인다 |
| **견고성** | 배율/위치/화질 교란(perturbation), `multi-scale` ≠ `scale perturbation` |
| **일반화** | val vs **holdout**, holdout 은 한 번만, **val 최고점을 고르면 안 되는 이유** |
| **실험 설계** | 사전 등록 판정 기준, 같은 실행 안에서 비교, 2×2 요인 설계, 잡음 폭(noise band) |
| **의료 AI 안전** | recall 우선 임계값, 확률 보정(calibration), 거절(abstention), 촬영 가이드 |
| **2단계 설계** | 단계마다 **입력도 증강도 백본도 다를 수 있다** (한쪽 결론을 옮겨 적지 않기) |
| **엔지니어링** | 조용한 실패를 시끄럽게, 로직은 `src/`(노트북 셀은 갱신 안 됨), 가정을 데이터에서 읽기 |

### 이 프로젝트에서 **틀렸다가 고친 것**

스킬 목록만큼 남겨둘 값어치가 있는 부분입니다.

| 틀렸던 것 | 실제 |
|---|---|
| JSON 스키마를 추측함 | 실물과 **3곳** 달랐음 → `diagnose.py` 로 확인 후 재작성 |
| "1단계도 2단계 크롭을 따라간다" | 아닙니다. 크롭 창이 정답을 흘려서 1단계는 `full` |
| "m2.5 는 macro-F1 대가가 없다" | 측정 4회 → 작지만 실재하는 대가(−0.027) |
| "`photometric` 은 나쁘다" | **2단계만** 그렇습니다. 1단계에서는 지름길을 막는 약 |
| "03 이 holdout 을 연다" | 아닙니다. 03 = val, **05 = holdout** |
| 잡음 폭 ±3%p | 반복 측정 → **±8%p** |
