## 1. holdout 을 처음 열었습니다 (STEP 5, 24.6분)

> 📘 **holdout 이란**: 학습에도 **모델 선택에도** 한 번도 안 쓴, 완전히 봉인해 둔 데이터.
> val(검증셋)은 "어떤 설정이 좋은가" 를 고르는 데 계속 써서, 우리도 모르게
> **val 에 맞춰 최적화**됩니다. holdout 은 그 오염이 없는 마지막 시험지입니다.
>
> 그래서 **한 번만 엽니다.** 열어보고 설정을 바꾸면 그 순간 holdout 도 val 이 됩니다.

| | val | **holdout** | |
|---|---:|---:|---|
| 1단계 AUROC | 0.8143 | **0.7412** | ❌ 목표 0.80 미달 |
| 2단계 macro-F1 | 0.5313 | **0.5582** | ✅ 오히려 상승 |
| 스크리닝 recall | 0.950 | **0.9303** | ❌ 목표 0.95 미달 |
| 헛알림 | 35% | **67.6%** | |
| **최종 7종 macro-F1** | — | **0.4432** | ← 보고할 숫자 |

**2단계는 개체가 바뀌어도 좋아지는데 1단계만 무너집니다.**

이게 왜 이상하냐면 — 보통 holdout 에서는 **둘 다** 조금씩 떨어집니다.
한쪽만 무너진다는 건 **그 단계에만 있는 무언가**가 일반화가 안 된다는 뜻입니다.

### 같이 얻은 것들

| 검사 | 결과 | 해석 |
|---|---|---|
| **Grad-CAM 정렬도** | lift **1.82**, 78% 가 우연 이상 | ✅ 배경이 아니라 병변을 봅니다 |
| **확률 보정(calibration)** | T=1.0531, ECE 0.0576 → 0.0548 | 원래도 크게 안 틀어져 있었음 |
| **거절(abstention)** | 절반 거절해도 오답 40.9% → 29.4% | ❌ 거절로는 정확도를 못 삽니다 |
| **촬영 가이드** | 아래 확정 | ✅ |

Grad-CAM 결과는 안심이 됩니다. Day 1 에 걱정했던 "배경 보고 맞히기" 는 아니었습니다.

### ✅ 촬영 가이드 확정

```
권장 : 병변이 화면 가로의 34% ~ 56%   (배율 0.85x~1.4x · 하락 5% 이내)
허용 : 28% ~ 68%                      (배율 0.7x~1.7x · 하락 10% 이내)
위치 : 병변이 화면 중앙에서 15% 이내
```

카메라 UI 에 가이드 프레임을 띄우고, 벗어나면 "조금 더 가까이/멀리" 를 띄웁니다.
이 구간 밖 사진은 **추론하지 말고 다시 찍게** 합니다.

⚠️ m2.5 로 바뀌면서 안내 문구도 바뀝니다. 1x 기준 병변의 화면 점유율이
m1.5 에서 약 67% 였는데 **m2.5 에서는 40%** — 즉 **더 넓게 찍으라**고 안내합니다.
움직이는 강아지를 상대로는 오히려 쉬운 요구입니다.

## 2. ★ 원인을 찾았습니다 — 화질 지름길 (STEP 6)

"1단계만 무너진다" 는 걸 보고 세운 가설:
**1단계가 병변이 아니라 다른 걸 보고 있는 게 아닐까?**

Day 1 에 만들어 둔 지름길 진단 도구를 화질 축으로 확장했습니다
(`robust.blur_stress()` — 사진을 점점 흐리게 하며 점수를 잽니다).

```
기존 1단계에 흐림(r=3)을 넣었더니:
  macro-F1      0.7430  →  0.3316
  balanced-acc  0.7...  →  0.5000   ← 동전 던지기
```

**완전히 무너집니다.** 그리고 데이터를 보니 답이 있었습니다:

```
정상 사진 선명도 중앙값 :  50
병변 사진 선명도 중앙값 : 274
```

> 💡 **모델이 배운 것**: "흐리면 정상, 선명하면 병변"
>
> 왜 이런 데이터가 됐을까요? 촬영자가 **병변을 발견하면 신경 써서 가까이 초점 맞춰**
> 찍고, 정상 부위는 대충 찍었을 겁니다. 사람에게는 자연스러운 행동인데,
> 모델에게는 **정답이 적힌 쪽지**가 됩니다.
>
> 그리고 이 쪽지는 **배포에 없습니다.** 보호자는 "병변인지 몰라서" 찍는 거니까요.
> 그래서 val 에서는 잘 되고 holdout·실사용에서 무너지는 겁니다.

### 2×2 실험으로 막았습니다 (서브셋 55% · 12에폭)

두 축을 동시에 봤습니다 — **백본**을 바꾸는 것과 **증강**으로 지름길을 막는 것.

| 백본 | 증강 | val AUROC | 흐림 하락 |
|---|---|---:|---:|
| effnetv2_s | default | **0.8359** | 47.6% |
| **effnetv2_s** | **photometric** | 0.8284 | **14.0%** ← 채택 |
| resnet50 | default | 0.8116 | 55.4% |
| resnet50 | photometric | 0.8145 | 16.9% |

**두 축 다 사전 등록 기준을 넘었습니다** — 증강 −38.5%p, 백본 +0.0244.

### ⚠️ val AUROC 최고를 안 골랐습니다

`effnetv2_s / default` 가 0.8359 로 제일 높습니다. 그런데 **흐림 하락이 47.6%** —
지름길에 기대고 있습니다. 그리고 AUROC 차이 0.0075 는 **잡음 안**입니다.

> **val 로 고르다 holdout 에서 무너진 게 바로 STEP 5 의 실패입니다.**
> 같은 실수를 반복하지 않습니다.

### ★ 그리고 여기서 Day 3 의 결론이 뒤집힙니다

Day 3 에 이렇게 적었습니다: **"`photometric` 은 macro-F1 을 0.03 깎는다. 나쁘다."**

맞습니다 — **2단계에서는.** 그런데 **1단계에서는 정반대**입니다:

| | 2단계 (Day 3) | 1단계 (오늘) |
|---|---|---|
| `photometric` 효과 | macro-F1 **−0.03** ❌ | 흐림 하락 **−38.5%p** ✅ AUROC 유지 |
| 왜 | 흐림이 **병변 질감(=라벨)** 을 지움 | 흐림이 **화질 지름길**을 지움 |

**같은 증강이 한 단계에는 독이고 다른 단계에는 약입니다.**
두 단계가 보는 것이 다르기 때문입니다 —
2단계는 "질감으로 종류 구분", 1단계는 "있냐 없냐". 후자에 질감 디테일은 덜 필요합니다.

> 💡 Day 4 에서 크롭이 단계마다 달라야 했던 것과 **같은 교훈**입니다.
> 한 단계에서 얻은 결론을 다른 단계에 옮겨 적으면 안 됩니다.

## 4. ⚠️ 잡음 폭을 다시 올렸습니다 (±3%p → ±8%p)

**2단계는 설정을 하나도 안 바꿨는데** 배율 하락이 실행마다 이렇게 나왔습니다:

| 실행 | 표본 | 배율 하락 |
|---|---:|---:|
| STEP 4D | 2,000 | 16.0% |
| STEP 5 | 2,000 | 21.6% |
| STEP 5 | 3,000 | 16.8% |
| STEP 7 | 2,000 | **23.8%** |

폭이 **7.8%p**. Day 4 에 쓴 ±3%p 도, 중간에 올린 ±5%p 도 낙관적이었습니다.

이번엔 **1.41x 가 1x 보다 높게** 나와서 "최고점이 1x" 라는 것조차 흔들립니다.
→ 촬영 가이드 밴드 경계를 **소수점까지 믿으면 안 됩니다.**
(다만 **형태** — 0.5x 에서 확 나빠짐 — 은 네 번 다 같습니다.)

> 💡 이건 실패가 아니라 **측정에 대한 정직한 갱신**입니다.
> 잡음 폭을 좁게 잡으면 없는 효과를 있다고 믿게 됩니다.
> 같은 이유로 **A6 recall 은 지금 잴 수가 없습니다** —
> 검증 표본이 ~256장뿐이라 2σ 가 ±0.085 인데, 목표 개선폭이 +0.095 입니다.
> **A6 을 고치기 전에 재는 방법을 먼저 고쳐야 합니다.**

## 5. 오늘의 버그 — 백본이 안 맞아서 05 가 죽었습니다

```
RuntimeError: size mismatch for bn1.weight:
  copying a param with shape torch.Size([24]) from checkpoint,
  the shape in current model is torch.Size([64])
```

05 에 **"03 의 체크포인트는 항상 resnet50"** 이라는 가정이 하드코딩돼 있었습니다.
STEP 6 에서 1단계를 effnetv2_s 로 바꾸면서 그 가정이 깨진 겁니다.
`effnetv2_s` 가중치를 **resnet50 껍데기**에 부으려다 채널 수가 안 맞아 죽었습니다.

고친 방법 — **백본을 폴더 이름에서 읽습니다**:

```python
train.model_key_from_exp("stage1_effnetv2_s_full_384_moderate_photometric")
# → "effnetv2_s"
```

그리고 `models.load_checkpoint` 가 이 에러를 만나면
**"백본이 다릅니다" 라고 한국어로 설명**하도록 바꿨습니다. 검사 4개 추가 (96/96 통과).

> 💡 **패턴이 보입니다.** Day 4 의 `cfg2` 오타, 오늘의 하드코딩 —
> 둘 다 **"어제까지 맞았던 가정이 오늘 깨진 것"** 입니다.
> 그래서 고칠 때 그 한 줄만 고치지 않고, **가정을 데이터에서 읽어오게** 바꿉니다.

## 6. 오늘 배운 것

1. **holdout 은 마지막에 한 번만 엽니다.** 열고 설정을 바꾸면 그것도 val 이 됩니다.

3. **화질 지름길**: 정상 50 / 병변 274 → "흐리면 정상". `photometric` 으로 막았습니다.
4. **같은 증강이 단계마다 정반대**일 수 있습니다 (2단계 독 / 1단계 약).
5. **val 최고점을 고르지 않습니다.** 견고성을 같이 봅니다.
6. **잡음 폭을 넓히는 것도 결과입니다** (±3 → ±8%p).
